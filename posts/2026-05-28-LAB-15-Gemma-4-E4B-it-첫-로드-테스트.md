## 목적

- 본격적인 실험 전에 Gemma 4 E4B-it 모델을 양자화로 RTX 5070에 실제 로드 가능한지 검증
- Transformers 5.9.0이 Gemma 4 멀티모달 클래스를 인식하는지 확인
- 더미 입력을 주어서 forward pass까지 동작하는지 확인

## 검증 범위

- 모델 가중치 로드 -> forward pass까지
- 실제 한국어 ARS 동작은 다음 회차에 다룰 예정

---

![](https://velog.velcdn.com/images/xorms/post/94b3b35b-70e9-43a2-be9e-69f48d033d08/image.png)

#### 위 결과를 통해서 확인된 내용

- architectures: ['Gemma4ForConditionalGeneration'] -> 로드에 쓸 정확한 클래스명
- model_type: gemma4 -> AutoModel 매핑 키
- audio_config 존재 -> 오디오 입력 받음
- vision_config 존재 -> 이미지도 받음
- text_config -> 텍스트 백본
- 즉, 텍스트 + 오디오 + 비전 통합 멀티모달

![](https://velog.velcdn.com/images/xorms/post/93aa2174-f220-43da-9e7a-ad1a147f45cc/image.png)

#### 위 결과를 통해서 확인된 내용

- AutoProcessor.from_pretrained -> Gemma4Processor 자동 로드 (셀 2.7 매핑 예측과 일치)
- 하위 구성요소:
  - tokenizer: GemmaTokenizer (텍스트)
  - feature_extractor: Gemma4AudioFeatureExtractor (오디오)
  - image_processor: Gemma4ImageProcessor (이미지)
- 즉, 프로세서 인스턴스 레벨에서 오디오 전처리기 확인

![](https://velog.velcdn.com/images/xorms/post/ef15b234-f3f5-4953-8f07-20b269f5702b/image.png)

#### 위 결과를 통해서 확인된 내용

- Gemma4ForConditionalGeneration + NF4 양자화로 로드 성공 (9.7초)
- Blackwell sm_120 + bitsandbytes NF4 첫 실작동 검증
- VRAM allocated: 8.665 GB / 11.94 GB (72.6%)
- 양자화는 Transformer 레이어에만 적용, 임베딩(256k 어휘) + 오디오/비전 인코더는 bf16 유지 -> 단순 추정(4GB)보다 높게 나옴
- 로드 직후 여유 약 3.3GB (추론 시 KV cache 공간)

![](https://velog.velcdn.com/images/xorms/post/50ef3a25-1b83-403e-b537-29b52aff4312/image.png)

#### 위 결과를 통해서 확인된 내용

확인 내용:

- 텍스트 더미 입력으로 generate() 동작 검증 (오디오 전 모델 자체 격리 테스트)

전달한 텍스트 프롬포트

```python
messages = [
    {"role": "user", "content": "안녕하세요. 한 문장으로 자기소개 해주세요."}
]
```

- peak VRAM: 8.726 GB (로드 대비 +0.061GB, KV cache 여유 충분)
