# [ 졸업작품 기록 (9) ]

하드웨어 구성 — 부품 선정과 3단계 필터링 구조

초인종 유사도 비교 방법을 정리하고 나서 전체 하드웨어 구성을 확정했다.
부품 하나하나를 고를 때 대안과 비교하면서 이유를 따져봤고,
설계 구조 관점에서도 정리해봤다.

## 전체 흐름

```
사람 접근
    ↓
PIR 감지 (1차 트리거)
    ↓
VL53L0X 거리 확인 (2차 필터, 1.5m 이내)
    ↓
INMP441 오디오 수집
    ↓
ESP32가 WAV 패키징 후 HTTPS POST
    ↓
Flask 서버 ML 처리 (소리 분류)
    ↓
카카오톡 알림
```

## 부품 선정

### ESP32-WROOM-32 (개발 보드)

Wi-Fi, I2S, I2C, GPIO를 하나의 칩에서 전부 처리할 수 있었던 게 결정적이었다.

Arduino Uno는 Wi-Fi 모듈을 따로 달아야 하고, Raspberry Pi는 이 용도에 쓰기엔 과사양이었다. ESP32가 딱 맞는 선택이었다.

### INMP441 (마이크)

I2S 디지털 출력 방식이라 노이즈가 적었다. 아날로그 마이크는 ADC 변환 과정이 필요하고 그 과정에서 노이즈가 섞이는데, INMP441은 디지털 신호로 바로 전달되라서 ML 입력 품질에 유리했다.

### HC-SR501 (PIR)

GPIO 신호만 읽으면 되는 구조라 구현이 단순했다. 카메라 기반 감지는 프라이버시 문제가 생기고 복잡도가 급격히 올라가는 반면, PIR은 "사람 있다 / 없다"만 판단하면 돼서 이 프로젝트 용도에 딱 맞았다.

### VL53L0X (ToF 거리 센서)

I2C 연결, 최대 2m 측정, 정밀도가 높다는 점에서 선택했는데, 사실 이 선택이 나중에 생각지도 못한 장점이 하나 더 있다는 걸 깨달았다.

초음파 센서(HC-SR04)로 갔으면 센서 자체가 소리를 발생시킨다. 그러면 INMP441 오디오 수집에 간섭할 가능성이 생기는 건데, ToF는 레이저 기반이라 그 가능성이 아예 없었다. 결과적으로 ToF 선택이 소리 수집 환경 보호까지 챙긴 셈이 됐다.

## 설계 구조 관점: 3단계 필터링

```
1단계: PIR (센서 레벨)
    → 사람 있냐 없냐

2단계: VL53L0X (센서 레벨)
    → 1.5m 이내냐 아니냐

3단계: YAMNet + 코사인 유사도 (ML 레벨)
    → 어떤 소리냐, 등록된 초인종이랑 일치하냐
```

1, 2단계를 센서 레벨에서 먼저 걸러내는 구조라서 Flask 서버까지 요청이 넘어오는 경우 자체가 줄어든다. 서버 부하를 최소화할 수 있는 구조였다.

## 5초 이내 알림 전송 목표 관점

| 단계 | 예상 소요 시간 |
| --- | --- |
| PIR + ToF 감지 | ~0.1초 |
| 오디오 수집 (2초 고정) | 2초 |
| WAV 패키징 + 전송 | ~0.5초 |
| Flask ML 추론 (YAMNet + 유사도) | ~1~2초 |
| 카카오톡 API 호출 | ~0.5초 |
| **합계** | **~4.1~5.1초** |

t2.micro가 버벅이면 t2.small로 업그레이드하는 걸 고려하기로 했다.

## 리스크

### PIR 감지 딜레이

HC-SR501은 감지 후 2~3초간 HIGH를 유지하는 특성이 있었다. 실제 구현할 때 이 딜레이를 파악하고 펌웨어 로직에 반영해야 했다. 그냥 두면 이미 사람이 떠난 상황에서도 감지된 것처럼 동작할 수 있었다.

### VL53L0X 설치 각도

현관문에 부착할 때 센서 방향에 따라 측정값이 튀는 경우가 있었다. 1.5m 임계값은 시연 환경에서 실측 후 조정하는 걸로 남겨뒀다.
