# ML 모델 선정 — YAMNet + Fine-tuning, TensorFlow

> 멜 스펙트로그램과 CNN 개념을 정리하고 나니 자연스럽게 다음 질문이 나왔다.
> "CNN 구조를 직접 설계할 것인가, 아니면 검증된 모델을 가져다 쓸 것인가"
> 이번 글에서는 그 선택 과정을 기록했다.

---

## 아키텍처란

CNN을 구성하는 레이어들을 어떤 순서로, 몇 개나, 어떤 방식으로 쌓을 것인지에 대한 설계도다.

같은 멜 스펙트로그램을 입력시켜도 아키텍처에 따라 정확도, 속도, 복잡도가 전부 달라지는데, 아키텍처가 결정하는 게 꽤 많다.

- **Conv 레이어 깊이** — 깊을수록 더 복잡한 패턴을 인식할 수 있음
- **필터 크기/개수** — 크기는 한 번에 보는 영역의 범위, 개수는 동시에 추출할 특징의 수
- **Pooling 위치** — 너무 일찍 넣으면 정보 손실, 너무 늦으면 연산 낭비
- **Dropout / BatchNorm** — 과적합 억제와 학습 안정화
- **FC 레이어 개수** — 너무 많으면 과적합, 너무 적으면 정확도 손해

---

## 선택지 비교: Custom CNN vs Transfer Learning vs Fine-tuning

### Custom CNN

Conv, Pooling, FC 레이어를 직접 조합해서 처음부터 설계하는 방식이다.

사전학습된 가중치 없이 내 데이터로만 처음부터 학습시킨다.

장점은 구조를 직접 설명할 수 있다는 점이었다. 심사위원 입장에서 학생이 모델을 직접 이해하고 설계했다는 게 보이는 구조라서 발표 때 유리하다. 모델도 가벼워서 Flask 서버 추론 속도도 빠르다.

단점은 데이터가 충분해야 하고, 설계 시행착오가 많다는 것이었다.

### Transfer Learning

다른 데이터로 이미 학습된 모델을 가져와서 내 문제에 맞게 재활용하는 방식이다.

앞부분 레이어(특징 추출)는 고정하고, 뒷부분 FC 레이어만 내 데이터로 새로 학습시킨다.

멜 스펙트로그램은 결국 2D 이미지라서, 이미지 분류용으로 학습된 모델을 소리 분류에 그대로 활용할 수 있다는 게 핵심 아이디어였다.

데이터가 적어도 90% 정확도 달성이 Custom CNN보다 훨씬 쉽고, 학습 시간도 짧다. 다만 "왜 이 아키텍처를 썼냐"는 질문에 "가져다 썼습니다"가 되는 게 단점이었다.

### Fine-tuning

Transfer Learning의 사전학습 모델을 가져오되, 앞부분 레이어도 내 데이터로 추가 학습시키는 방식이다.

사전학습 모델이 이미 소리의 기본 특징은 알고 있으니, Fine-tuning으로 초인종/노크/화재경보 특화 특징을 추가 학습시키는 구조였다.

정확도는 Transfer Learning 수준으로 확보하면서, 발표 때 "Fine-tuning을 통해 우리 도메인에 최적화했습니다"라고 설명할 수 있다는 점이 마음에 들었다.

## 오디오 특화 사전학습 모델 비교

### VGGish

Google이 2017년에 만든 오디오 특화 사전학습 모델인데, VGG(이미지 분류 모델)를 오디오용으로 바꾼 것이다.

YouTube 오디오 800만 개로 학습되어 있고, 멜 스펙트로그램을 입력으로 받아 128차원 임베딩 벡터를 출력한다.

이 128차원 벡터 뒤에 FC 레이어를 하나 더 붙이면 3가지 클래스로 분류할 수 있다.

### YAMNet

Google이 VGGish 이후에 만든 모델이다.

AudioSet 521개 클래스로 학습되어 있고, 일반 Conv 대신 **Depthwise Separable Convolution**을 쓴다.

일반 Conv는 특징 추출과 채널 조합을 한 번에 하는데, Depthwise Separable Conv는 이걸 두 단계로 쪼갰다.

1. **Depthwise Conv** — 각 채널을 독립적으로 처리해서 특징 추출
2. **Pointwise Conv** — 1×1 필터로 채널 조합

연산량이 대폭 줄어드는 구조라서 VGGish보다 가볍고 추론이 빠르다.

---

## YAMNet + Fine-tuning을 선택한 이유

세 가지가 결정적이었다.

첫째, **추론 속도**다. Depthwise Separable Conv 구조 덕분에 모델이 가벼워서, 소리 감지 후 알림까지 5초 이내라는 요구사항에 유리했다.

둘째, **학습 데이터와의 직접적인 겹침**이다. YAMNet이 학습된 AudioSet에 초인종/노크/화재경보가 전부 포함되어 있어서, Fine-tuning 효과가 극대화될 수 있었다.

셋째, **서버 비용**이다. 모델이 가벼울수록 Flask 서버의 추론 부담이 줄어들고, 클라우드 비용도 낮아진다.

## 프레임워크 선정: TensorFlow + Keras

### TensorFlow vs PyTorch

|  | TensorFlow | PyTorch |
| --- | --- | --- |
| 개발사 | Google | Meta |
| 방식 | 설계도를 먼저 만들고 데이터를 나중에 실행 | 코드를 짜면서 바로바로 실행 |
| 디버깅 | 상대적으로 불편 | 직관적 |
| YAMNet 지원 | 공식 지원 | 비공식 |

PyTorch는 Python 코드랑 거의 똑같이 생겨서 가독성이 좋고 디버깅이 직관적이었는데, YAMNet을 공식 지원 환경에서 그대로 가져다 쓰려면 TensorFlow가 맞았다.

Keras는 TensorFlow를 더 쉽게 쓸 수 있게 해주는 고수준 API라서 함께 사용하기로 했다.

**TensorFlow + Keras로 확정.**
