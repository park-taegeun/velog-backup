## 일반 파인튜닝의 문제

모델을 학습시킨다는 것 = 가중치 W를 업데이트하는 것

```
W: 4096 × 4096 행렬 = 약 1600만 개 파라미터
레이어가 수십 개 → 전체 수십억 개
```

이것을 모두 업데이트하려면 VRAM이 몇 배로 필요함

## LoRA의 핵심 관찰

***모델을 파인튜닝할 때 실제로 변하는 가중치의 변화량  ΔW는 rank가 낮다.***

- rank가 낮다 =  ΔW가 아무리 커 보여도 실제로 담고 있는 정보는 훨씬 작은 행렬 두 개로 표현 가능

## 그래서 어떻게 하냐

W를 직접 건드리는 대신

```
ΔW ≈ A × B

W: 4096 × 4096  (고정, 학습 안 함)
A: 4096 × 8     (학습)
B: 8 × 4096     (학습)
```

rank를 8로 잡으면 학습 파라미터가:

```
원래: 4096 × 4096 = 16,777,216개
LoRA: 4096×8 + 8×4096 = 65,536개
→ 약 256배 감소
```

-> 추론할 때는 W + A×B를 합쳐서 사용함

## rank가 뭔가

A×B의 "중간 차원"

- rank=4  → 더 작고 빠름, 표현력 낮음
- rank=8  → 균형 (가장 많이 쓰임)
- rank=16 → 표현력 높음, 메모리 더 씀

## Gemma4에 적용하면

```
audio_tower: 오디오 → 벡터 변환 (인코더)
LM 본체: 벡터 → 텍스트 생성 (디코더)
```

> *즉, LoRA는 **모델 가중치 W를 고정하고, 변화량 ΔW를 두 개의 작은 행렬로 근사해서 학습**하는 효율적 파인튜닝 기법이다.*
