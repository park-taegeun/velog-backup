# [ 졸업작품 기록 (8) ]

초인종 유사도 비교

교수님 피드백을 받고 나서 초인종 개인 등록 기능을 설계하기 시작했다.
막상 파고들어 보니 생각보다 고민할 게 많았고, 결국 센서를 두 개 더 추가하는 방향으로 흘러갔다.

## YAMNet 분류만으로는 부족한 이유

처음엔 YAMNet이 "초인종"으로 분류하면 끝이라고 생각했는데, 현실은 달랐다.

```
옆집 초인종이 울림
        ↓
ESP32가 소리 감지
        ↓
YAMNet: "초인종" (90% 확률)
        ↓
카카오톡 알림 전송
```

청각장애인 입장에서 옆집 초인종에 알림이 울리는 건 상당히 불편한 상황이다. 그래서 나온 게 초인종 개인 등록 기능이었다.

## 초인종 등록 방법

```
사용자가 자기 집 초인종을 3~5회 누름
        ↓
ESP32가 소리 녹음
        ↓
Flask 서버로 전송
        ↓
멜 스펙트로그램으로 변환
        ↓
SQLite에 템플릿으로 저장
```

여러 번 녹음해서 평균 템플릿을 만들면 한 번만 녹음하는 것보다 안정적이라서 3~5회로 잡았다.

## 유사도 비교 방법 선택

등록된 소리랑 새로 감지된 소리를 비교할 때, 소리 파형 자체를 비교하는 게 아니라 멜 스펙트로그램(2D 이미지)을 비교하는 방식이다.

여기서 첫 번째 문제가 생겼는데, 두 멜 스펙트로그램의 시간축 길이가 다를 수 있다는 거였다.

> 초인종을 짧게 누를 수도 있고 길게 누를 수도 있음 → 시간축 길이가 달라져서 단순 비교가 안 됨

### 선택지 1: DTW (Dynamic Time Warping)

두 시퀀스를 비교할 때 시간축을 유연하게 늘리거나 줄여서 가장 잘 맞는 지점끼리 대응시키는 알고리즘이다. 시간축 길이 문제를 가장 우아하게 해결하는 방법인데, 문제는 계산량이었다.

두 시퀀스 길이가 각각 N, M이면 계산량이 N × M인데, t2.micro 사양에서 5초 이내 응답 요건을 맞추기가 빠듯할 수 있었다.

### 선택지 2: 코사인 유사도

두 벡터가 얼마나 같은 방향을 가리키는지로 유사도를 측정하는 방법이다.

```
템플릿 멜 스펙트로그램 (2D) → 1D 벡터로 펼치기
새 소리 멜 스펙트로그램 (2D) → 1D 벡터로 펼치기
        ↓
두 벡터 사이 각도 계산
        ↓
각도가 작을수록 (1에 가까울수록) 유사한 소리
```

시간축 길이가 다르면 비교 전에 고정 길이로 맞춰야 한다는 전제조건이 있는데, 그건 이렇게 처리하기로 했다.

- 2초보다 길면 → 앞부분 2초만 사용
- 2초보다 짧으면 → 뒤에 0으로 패딩

### 코사인 유사도로 확정

초인종 소리는 DTW가 필요할 만큼 시간축 변형이 크지 않다고 판단했고, 계산이 빠르고 구현도 단순해서 t2.micro에서 5초 요건을 맞추기 훨씬 수월했다.

만약 실제로 돌려봤을 때 효과가 없으면 DTW + 서버 업그레이드(t2.small)를 고려할 예정이다.

- 등록 시: 녹음 → 2초로 고정 → 멜 스펙트로그램 → SQLite 저장
- 감지 시: 소리 → 2초로 고정 → 멜 스펙트로그램 → 코사인 유사도 계산

## 생각지 못했던 문제: 같은 아파트면 초인종 소리가 똑같다

코사인 유사도를 쓰기로 하고 나서 더 근본적인 문제가 보였다.

> 보통 같은 아파트면 초인종 제조사가 같음 → 집들끼리 초인종 소리가 똑같음

코사인 유사도로 비교할 때 임계값을 아무리 높여도, 소리 자체가 같으면 걸러낼 방법이 없다. 유사도 비교 방법의 문제가 아니라 소리 자체의 문제라서 소프트웨어만으로는 해결이 안 됐다.

그래서 추가 센서 두 가지를 고려하게 됐다.

## 추가 센서: PIR + ToF

### PIR — 사람 감지

사람 몸에서 나오는 적외선(열)을 감지하는 센서인데, 카메라처럼 영상을 찍는 게 아니라 "사람이 있다 / 없다"만 판단한다.

- 문 앞에 아무도 없음 → PIR 센서: 0 (감지 안 됨)
- 문 앞에 사람 있음 → PIR 센서: 1 (감지됨)

소리가 감지됐을 때 PIR도 1이면 실제로 누군가 문 앞에 있다는 거라서, 알림 발송의 1차 조건으로 쓸 수 있었다.

다만 PIR의 기본 감지 각도가 100~120도라 좁은 아파트 복도에서는 앞집까지 닿을 수 있다는 한계가 있었다. 각도를 좁히는 방법으로는 물리적으로 가리거나 센서 위치를 조정하는 방식을 고려했다.

### ToF — 정밀 거리 측정

PIR이 "사람이 있다"는 건 알려주지만, 얼마나 가까이 있는지는 알 수 없었다. 그래서 거리까지 측정하는 VL53L0X ToF 센서를 추가했다.

ToF는 레이저(적외선)를 발사해서 반사되어 돌아오는 시간으로 거리를 계산한다.

```
거리 = 빛의 속도 × 걸린 시간 / 2
```

초음파 센서도 거리 측정이 가능한데, 초음파는 소리라서 퍼져나가기 때문에 좁은 복도에서 벽이나 바닥에 반사된 신호가 섞이면 오차가 생긴다. ToF는 레이저라 직선으로 날아가서 복도 환경에서 훨씬 정확하게 거리를 잡을 수 있었다.

ESP32 연결은 I2C 통신으로 하는데,

```
VL53L0X    ESP32
SDA    →   GPIO 21
SCL    →   GPIO 22
VCC    →   3.3V
GND    →   GND
```

INMP441 마이크는 I2S 핀을 쓰고, ToF는 I2C 핀을 쓰니까 핀 충돌 없이 함께 연결할 수 있었다.

## 최종 필터링 흐름

```
소리 감지 (ESP32 + INMP441)
        ↓
YAMNet 1차 분류: "초인종"
        ↓
PIR 감지 확인 → 문 앞에 사람 없으면 알림 미전송
        ↓
ToF 거리 확인 → 1.5m 초과면 알림 미전송
        ↓
코사인 유사도 2차 필터 → 임계값 미만이면 알림 미전송
        ↓
카카오톡 알림 전송
```

소리 분류 → 사람 감지 → 거리 확인 → 유사도 비교, 이 네 단계를 모두 통과해야 알림이 간다. 오탐 가능성을 최대한 줄이는 구조였다.
