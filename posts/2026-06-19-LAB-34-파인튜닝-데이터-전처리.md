## 1. 데이터 전처리

이번 실험의 핵심 질문은 *파인튜닝이 모델의 **오디오 의존도**를 실제로 높이는가* 이다.

그래서 전처리도 단순히 깨끗한 텍스트 만들기가 아니라, **이 질문을 깨끗하게 측정할 수 있는 데이터를 만드는 것**을 기준으로 모든 결정을 내렸다.

- 텍스트를 깨끗하게
  - 지저분한거 지우고 단정하게 만들기
  - 노이즈 제거, 형식 통일
  - 목표는 예쁜 텍스트
- 측정이 깨끗하게
  - 본 파인튜닝 실험 질문: *파인튜닝이 오디오를 더 쓰게 만드냐?*
  - 이에 대한 답이 깨끗해지는 방향으로 전처리

아래 결정들이 왜 그렇게 됐는지가 이 글의 핵심이다.

### 1.1 데이터 구조

데이터셋은 KconfSpeech(한국어 회의/방송 음성)이고,
발화 단위로 16kHz 모노 wav와 별도의 txt 전사가 짝지어져 있다.

- 10개 세션(S000010~S000019), **총 3588 발화**
- 라벨 JSON의 `dialogs[i]` = {speaker, audioPath, textPath} 로 wav↔txt 페어링
- 단, JSON 경로가 `KconfSpeech/D23/G02/...` 프리픽스라 실제 디스크 구조(`wav/`, `label/`)와 달라서 매핑이 필요했다 (audioPath → `wav/`, textPath → `label/`)
- wav↔txt **1:1, 누락 0** 확인
- 화자 ID는 **세션-로컬**이다. 세션이 다르면 같은 "1"이라도 다른 사람 → 화자 단위 = (세션, 화자)

### 1.2 텍스트 정제

전사 원문은 KconfSpeech 주석 형식이라 그대로 못 쓴다. 예:

```
n/ 공기를 통해 에이즈를 전염시키는 변종 (HIV)/(에이치 아이 브이) 바이러스가 등장해...
```

여기엔 세 종류의 주석이 섞여 있고, 각각을 어떻게 처리할지가 **측정 품질을 좌우**한다.

**(1) 이중전사 `(표기)/(발음)` → 표기형 유지**

`(HIV)/(에이치 아이 브이)`, `(IMF)/(아이 엠 에프)`처럼 표기형과 발음형이 같이 적혀 있다. 발음형이 오디오와 더 맞아 보여서 처음엔 발음형을 쓰려 했다. 그런데 다시 따져보니 반대였다.

- 발음형을 정답으로 쓰면, 모델은 "IMF는 아이 엠 에프로 풀어 쓴다"는 **오디오와 무관한 규칙**을 새로 외워야 한다.
  -> 이건 한 번 외우면 오디오가 있든 없든 똑같이 적용되므로, 학습 전후 CER만 부풀리고 정작 우리가 보려는 **오디오 갭(오디오 의존도)에는 잡히지 않는다.**
- 표기형을 쓰면 베이스 모델이 원래 출력하는 형태와 가까워서, 학습 전후 차이가 **순수하게 오디오 기반 정확도**에서만 나온다.

즉 **표기형이 측정을 흐리지 않는다.**

**(2) 라틴 이벤트 태그 `o/ n/ l/ u/ b/` → 제거, `@/`(이름 마커)는 이름만 남김**

잡음·숨소리·웃음 등 비어휘 마커라 한국어 단어가 아니다.
`@/최광원`처럼 이름 앞에 붙는 마커는 `@/`만 떼고 이름은 살린다.

**(3) 한국어 필러 `어/ 에/ 음/...` → 유지**

필러(어, 음)는 **오직 오디오를 들어야만 어디서 나왔는지 알 수 있는** audio-dependent 신호 -> 텍스트 문맥만으로는 예측이 불가능하다.

- 정답에 필러를 남겨두면, 모델이 필러를 맞추려면 **반드시 오디오를 써야 한다.** 무음에서는 위치를 못 맞춰 틀린다 → **오디오 갭에 잡힌다.**
- 즉 필러는 우리 ablation의 민감도를 높여주는 신호라, 일부러 남긴다.

정제 결과 3588개 전부 통과, **빈 전사 0개**.

### 1.3 데이터 분할

분할도 "오디오 의존도를 어디서 가장 깨끗하게 잴 수 있나"를 거꾸로 따져서 정했다.

```
전체 3588 (10세션)
 └─ 홀드아웃 2세션: S000010(464) + S000017(364) = 828  → test (안 본 화자, 학습 X)
    = train+val 풀 2760
       ├─ val   275   (풀의 10%, 세션 층화)
       └─ train 2485
            └─ 1단계: train에서 추출 → train 480 / val 119 (파이프라인 검증용)
```

**왜 홀드아웃이 "세션"이고 "2개"인가**

- 홀드아웃 = 학습에 안 쓰고 따로 빼놓은 데이터
  -> 나중에 테스트용으로만 사용하기 위해서
- 화자가 세션-로컬이라, **세션을 통째로 빼면 그 세션의 화자도 학습에서 빠진다 = 안 본 화자.**
- 안 본 화자가 왜 중요한가: 같은 세션(본 화자)으로 평가하면 "오디오를 쓴다"가 "이 목소리를 외웠다"와 구분되지 않는다.
  -> **화자 암기를 배제한 깨끗한 오디오 조건화 측정은 안 본 화자에서만 가능**하다.
- 그래서 **헤드라인 audio-gap은 test(안 본 화자)에서** 재고, val(본 화자)은 보조 지표로 둔다.
- **2세션으로 늘려** test의 짧은 발화 262개 / 긴 발화 566개를 확보했다.
- 두 세션은 **포맷·주제가 다르게** 골랐다: S000010(뉴스 보도·전염병, 낭독체) + S000017(토크쇼·남녀, 자유대화체). 일반화 test가 두 발화 스타일을 모두 커버한다.

**왜 길이 필터를 안 거는가**

진단 단계에서 "짧은 발화 → 약한 오디오 조건화 → 환각"이 핵심 발견이었다.
그런데 짧은 발화를 빼면 **우리가 보려는 현상 자체를 빼버리는** 셈이다. 그래서 학습엔 다 쓰고, **평가만 short(≤30자) / long(>30자)으로 층화**해서 길이대별 오디오 갭을 본다.

### 1.4 audio-gap 측정 이유

핵심: ***모델이 오디오를 생각보다 안 쓴다***

- 짧은 발화에선 모델이 오디오를 무시하고 자기 언어모델 감(prior)로 지어냄 = 환각
- 그렇다면 오디오를 빼도(무음) 출력이 별로 안 바뀜 -> 어차피 안 쓰니까
- 즉 "무음 줘도 별로 안 나빠진다" = 모델이 오디오를 무시하고 있었다는 증거
  -> audio-gap이 작게 나오는 케이스가 우리가 잡고 싶은 문제

반대로 긴 발화처럼 오디오를 진짜 쓰는 데선 무음 주면 갭이 커진다.
즉, 갭은 항상 큰게 아니라 상황 따라 다르고 그 차이가 곧 오디오 의존도인 것이다.

추가로 본 실험에서 확인하는 것은 절대 크기가 아니라 **짧은 발화에서 파인튜닝 전 vs 후로 갭이 커졌나?**

```
환각 = 오디오 무시하고 prior로 지어냄
audio-gap이 작다 = 오디오 빼도 출력 안 바뀐다. = 오디오 무시하고 있었음
```
