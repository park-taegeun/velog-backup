## PhotoCraft란 무엇인가

### 배경

PhotoCraft는 ArtCraft 창업자 Brandon Thomas가 Claude Opus 5.5로 만든 Adobe 클론 앱 7개 중 하나로, Photoshop에 대응하는 이미지 편집 앱입니다. 순수 Rust로 작성되었고 2026년 9월 30일에 첫 커밋이 올라왔습니다. 라이선스는 MIT/Apache-2.0이며, 실습 시점 버전은 v0.8.2로 아직 early alpha(기능은 동작하지만 안정성은 보장되지 않는 초기 단계)입니다.

### 클린룸 구현

PhotoCraft는 클린룸(clean-room) 방식으로 만들어졌습니다. 원본 제품의 코드나 에셋을 쓰지 않고, 공개된 스펙과 겉으로 보이는 동작만 참고해 처음부터 새로 만드는 방식입니다. 기존 소프트웨어와 비슷하게 동작하는 제품을 만들면서도 코드를 베꼈다는 문제를 피하고 싶을 때 쓰는 방법입니다. 덕분에 포토샵 사용자에게 익숙한 "변수·데이터 세트" 같은 기능을 그대로 만날 수 있습니다.

### 명령 레지스트리와 MCP 도구 25개

PhotoCraft의 500개가 넘는 기능은 모두 명령(command) 하나의 레지스트리(registry, 명령을 이름으로 등록해두는 목록)에 들어 있습니다. UI 버튼도, CLI도, MCP도 전부 같은 명령을 호출합니다.

그런데 MCP 도구는 25개뿐입니다. **리모컨 버튼 25개로 명령 500개를 부르는 구조**입니다. 예를 들어 글자 레이어를 만들고 싶으면 `command_list`로 명령을 찾고, `command_run`으로 `type.create`를 실행합니다. 기능마다 도구를 하나씩 만들었다면 도구 설명서만으로 컨텍스트를 크게 차지했겠지만, 이 구조는 설명서가 작아 토큰 절약에 유리합니다.

## 설치 및 MCP 등록

### 무결성과 공증 확인

알파 버전 실행 파일을 내려받는 만큼 두 가지를 먼저 확인했습니다.

- **sha256 해시**: 파일 내용으로 계산한 지문입니다. 배포자가 공개한 값과 같으면 다운로드 과정에서 바뀌지 않았다는 뜻입니다.
- **Apple 공증(notarization)**: Apple이 악성코드 검사를 거친 앱에 붙여주는 확인 표시입니다.

```bash
shasum -a 256 ~/Downloads/photocraft-cli-0.8.2-macos-universal.zip
# 릴리스 페이지의 sha256 값(38fd0463f20bc...)과 일치 확인

mkdir -p ~/tools/photocraft
ditto -x -k ~/Downloads/photocraft-cli-0.8.2-macos-universal.zip ~/tools/
mv ~/tools/photocraft-cli-0.8.2-macos-universal/photocraft-cli ~/tools/photocraft/
spctl --assess --type install -vv ~/tools/photocraft/photocraft-cli
# accepted, Notarized Developer ID
```

실행 파일은 버전 번호가 없는 고정 경로(`~/tools/photocraft`)에 두었습니다. 새 버전으로 교체해도 경로가 같아서 MCP를 다시 등록할 필요가 없습니다.

### 필요한 기능이 있는지 먼저 확인

```bash
~/tools/photocraft/photocraft-cli commands | grep -i -E "type|text"
~/tools/photocraft/photocraft-cli commands | grep -i -E "dataset|variable"
```

`type.create`, `type.edit`, `edit.findAndReplaceText`, `image.variables.define`, `file.export.dataSetsAsFiles` 등 카드뉴스에 필요한 명령이 모두 있었습니다.

### 헤드리스 모드와 폴더 출입증

PhotoCraft는 두 가지 방식으로 조종할 수 있습니다.

- **헤드리스(headless)**: 화면 없이 엔진만 실행합니다. 사람이 지켜볼 필요 없는 자동화에 적합합니다.
- **브리지(bridge)**: 켜져 있는 앱을 원격 조종합니다. 작업 과정을 눈으로 보며 함께 편집할 때 적합합니다.

자동화가 목적이므로 `--automation-read-root`, `--automation-write-root`로 읽고 쓸 수 있는 폴더를 지정해 등록했습니다. 일종의 **폴더 출입증**으로, 지정하지 않으면 파일을 전혀 다룰 수 없습니다.

```bash
mkdir -p ~/cardnews
claude mcp add photocraft --scope user -- \
  /Users/xorms/tools/photocraft/photocraft-cli mcp \
  --automation-read-root /Users/xorms/cardnews \
  --automation-write-root /Users/xorms/cardnews
```

`✔ Connected`와 `/mcp`의 도구 25개를 확인했습니다. 배경 이미지 같은 소재도 출입증 폴더 안으로 복사해야 쓸 수 있습니다.

## 단일 실습 — 템플릿에서 데이터 세트까지

### 1. 테스트 카드로 한글 폰트 확인

1080x1350 새 문서에 "AI 뉴스 테스트" 글자 레이어를 넣고 PNG로 저장한 뒤, Claude가 PNG를 직접 열어 한글이 □로 깨지지 않았는지 확인했습니다. `type.fonts`는 폰트 이름만 알려주고 한글 지원 여부는 알려주지 않아서, Claude가 `fc-list :lang=ko` 결과와 교차 확인했습니다.

[이미지: v1 테스트 카드]

### 2. 자리표시자 템플릿

`{{제목}}`, `{{본문}}`, `{{출처}}` 레이어로 `template.pcraft`를 저장한 뒤, 다시 열어 자리표시자가 살아 있는지 **왕복 검증**했습니다. hwp-mcp 편에서 얻은 "저장 완료를 믿지 말고 다시 읽어라"는 교훈을 그대로 적용한 것입니다. 이후 `findAndReplaceText`로 각 1건씩 치환해 `card_test.png`를 만들었습니다.

### 3. 데이터 세트로 3장 한 번에

데이터 세트(Variables & Data Sets)는 포토샵의 기능을 그대로 구현한 것으로, **같은 디자인에 내용만 다른 이미지를 여러 장 찍어낼 때** 씁니다.

- **변수**: 레이어에 붙이는 이름표
- **CSV 헤더**: 이름표 이름
- **CSV 한 줄**: 카드 한 장

예를 들어 이벤트 명찰 100장이 필요하다면 CSV 100줄이면 됩니다. 변수 이름은 인코딩 문제를 피하려고 영어(`title`, `body`, `source`)로 지정했습니다.

```csv
title,body,source
"첫 번째 제목","본문 첫 줄
본문 둘째 줄","출처 A"
```

3줄짜리 테스트 CSV로 PNG 3장이 한 번에 생성됐고, CSV에 직접 넣은 줄바꿈도 그대로 전달됐습니다.

[이미지: 데이터 세트로 생성된 테스트 카드 3장]

### .pcraft와 .png의 차이

- **.pcraft**: 레이어가 살아 있는 원본입니다. 포토샵의 .psd와 같습니다.
- **.png**: 레이어가 합쳐진(flatten) 결과물입니다.

PNG로 저장하면 "layer(s) flattened" 경고가 뜹니다. **템플릿은 반드시 .pcraft로, 결과물만 PNG로** 저장해야 합니다.

## 한국어 줄바꿈 문제 해결기

### 증상 — 단어 중간이 잘린다

PhotoCraft는 한글을 **글자 단위로** 자동 줄바꿈합니다. 그래서 "읽고,"가 "읽 / 고,"처럼 단어 중간에서 잘렸습니다. 띄어쓰기 기준으로 줄을 바꾸는 어절 단위 설정은 없었습니다.

[이미지: 단어 중간이 잘린 카드]

### 1차 해결 — 규칙으로 막기

CSV에 줄바꿈을 직접 넣고, 한 줄 글자 수를 제한했습니다. 하지만 규칙은 지켜질 때만 효과가 있습니다. 한 줄이 조금만 길어져도 글상자가 다시 자동 줄바꿈을 해버립니다.

### 최종 해결 — 구조로 막기

글자 레이어를 **포인트 텍스트**로 바꿨습니다.

- **단락 텍스트(글상자)**: 상자 폭에 맞춰 자동으로 줄을 바꿉니다.
- **포인트 텍스트**: 상자 없이 찍은 위치에서 글자가 이어집니다. 자동 줄바꿈이 없습니다.

포인트 텍스트로 바꾸자 줄은 CSV에 넣은 위치에서만 바뀌게 됐습니다. 남은 과제는 "한 줄에 몇 글자까지 들어가는가"였습니다. 그래서 Pretendard Bold 기준 **한글 1자 폭이 0.864em**이라는 값을 실측했습니다. em은 글자 크기를 1로 보는 단위로, 예를 들어 64px 제목이라면 한 글자 폭은 약 55px입니다. 이 값으로 변수별 "최대 줄 수 / 한 줄 최대 글자 수"를 계산해 규칙 파일 `변수규칙_v3.md`로 정리했습니다.

데이터 세트는 레이어 위치가 고정되어 있다는 점도 고려했습니다. 제목이 1줄일 때와 3줄일 때 아래 요소와 겹칠 수 있기 때문에, "제목 2줄 고정", "표지 제목 3줄 고정" 같은 카피 규칙으로 레이아웃을 맞췄습니다.

### 역할 분담

- **Claude**: 규칙을 지키며 카피를 쓰는 유연한 일
- **PhotoCraft**: 받은 글자를 그대로 찍어내는 정확한 일

도구가 못 하는 것을 억지로 시키지 않고, 각자 잘하는 일을 나눈 것이 해결의 핵심이었습니다.

## 디자인 개선 루프 — AI 디자이너와 블라인드 AI 검토자

### 역할 부여는 기준과 함께

역할 부여(role prompting)는 AI에게 특정 전문가의 관점을 주는 방법입니다. 하지만 "베테랑 디자이너처럼 봐줘"만으로는 막연합니다. 그 사람이 실제로 보는 기준을 같이 줘야 구체적인 피드백이 나옵니다. 이번에는 위계, 썸네일 가독성, 여백, 대비, 타이포, 색, 시리즈 일관성, 정보 밀도 8개 기준을 각 10점씩 80점 만점으로 채점하게 했습니다.

### 블라인드 검토 — 만든 쪽이 채점하지 않기

만든 쪽이 채점하면 점수가 후해집니다. 그래서 제작 과정을 모르는 **별도 서브에이전트에게 PNG만 주고 채점**하게 했습니다. 14편에서 다룬 Nested Agent를 검토자로 활용한 것입니다. 검토자는 감으로 보지 않고 직접 측정했습니다.

- 360px 축소본을 실제로 만들어 인스타그램 피드 썸네일에서도 읽히는지 확인
- 픽셀 색을 뽑아 WCAG(웹 콘텐츠 접근성 지침) 기준의 글자-배경 대비비 계산
- 그라데이션 위 글자는 **글자 뒤에서 가장 밝은(또는 어두운) 지점**을 기준으로 측정

### 레퍼런스 리서치 — 무드보드

무드보드(mood board)는 디자인 방향을 정하기 위해 참고 이미지를 모아둔 판입니다. 웹 검색과 Firecrawl로 트렌드 글을 모으고, Playwright로 페이지를 열어 스크린샷을 찍은 뒤 Claude가 직접 보고 분석했습니다. 하나를 따라 하지 않고 여러 레퍼런스의 **공통 패턴**을 뽑았습니다.

| 공통 패턴 | 내용 |
|---|---|
| 배경 | 남색 바탕 + 빛 번짐 |
| 질감 | 그레인(필름 같은 미세한 입자) |
| 위계 | 큰 제목 + 작은 키커(제목 위의 짧은 분류 문구) |
| 반복 장치 | 진행 표시처럼 시리즈를 묶어주는 요소 |
| 구조 | 얇은 선(헤어라인)으로 나눈 레이아웃 |
| 카피 | 봐야 할 이유를 쓴 문장 |

참고한 레퍼런스: [링크 — 한 줄 설명]

새 기준인 "전문 디자이너 완성도"는 두 시안 모두 5/10이었습니다. 또 검토자가 바뀌면 1~2점은 쉽게 흔들렸습니다. **점수보다 지적 내용을 보는 것이 더 정확합니다.**

큰 페이지 번호는 처음에 탁한 회색 덩어리로 보였는데, Normal 9%에서 Overlay 블렌드(아래 배경 색이 비쳐 보이도록 섞는 혼합 모드)로 바꿔 해결했습니다.

### 수확 체감과 사람-AI 분업

반복할수록 시간은 늘고 점수 상승 폭은 줄었습니다. 시안 3개는 약 7분이었지만 v3는 약 17분이 걸렸습니다. 투입을 늘려도 얻는 효과가 점점 줄어드는 **수확 체감(diminishing returns)**입니다.

완성도의 한계는 레퍼런스에 있었습니다. AI가 인스타그램(로그인 필요)과 Behance(접근 차단)를 볼 수 없어 참고할 수 있는 디자인이 부족했습니다. 그래서 가짜 데이터로 디자인을 더 다듬기보다 실제 데이터로 넘어가 실전 문제를 고치는 쪽을 택했습니다. 이 과정에서 정리한 사람의 역할은 세 가지입니다. **취향 선택, 레퍼런스 제공, 최종 팩트체크**입니다.

### 팩트 안전장치

뉴스는 틀리면 안 되기 때문에 세 가지 장치를 두었습니다.

- **highlight 변수 제외**: "핵심 수치" 같은 칸을 만들지 않았습니다. 기사에 숫자가 없을 때 AI가 칸을 채우려고 숫자를 지어낼 위험이 있기 때문입니다.
- **facts.md**: 카드마다 근거가 된 기사 문장과 링크를 기록했습니다. 사람이 어디를 확인하면 되는지 바로 보입니다.
- **자기 수정 루프**: 검증에서 걸린 카드를 Claude가 스스로 고쳐 다시 내보냅니다. 실제로 4번 카드의 제목이 기사보다 범위가 좁게 표현된 것을 발견해 1회 수정했습니다.

## 트러블슈팅 요약

| 문제 | 해결 |
|---|---|
| 폴더 출입증 미지정 시 파일 접근 불가 | read/write root 지정, 소재 파일도 해당 폴더로 복사 |
| `type.fonts`로 한글 지원 여부 알 수 없음 | `fc-list :lang=ko`와 교차 확인 |
| PNG 저장 시 "layer(s) flattened" 경고 | 템플릿은 .pcraft, 결과물만 PNG |
| 한국어 글자 단위 줄바꿈 | 포인트 텍스트 + CSV 수동 줄바꿈 + 실측 글자 폭 규칙 |
| 데이터 세트의 레이어 위치 고정 | "제목 2줄 고정" 같은 카피 규칙 |
| 큰 페이지 번호가 탁한 회색으로 보임 | Normal 9% → Overlay 블렌드 |
| 인스타그램·Behance·Canva 접근 제한 | 사람이 레퍼런스를 제공하는 분업 |
| Claude Code가 영어로 답변 | `~/.claude/CLAUDE.md`에 "항상 한국어로 답변할 것" 추가 |
| v3 템플릿 용량 약 4.7MB (v2 약 0.2MB) | 빛 번짐·그레인이 픽셀 레이어라 생긴 차이로, 감안하고 사용 |
