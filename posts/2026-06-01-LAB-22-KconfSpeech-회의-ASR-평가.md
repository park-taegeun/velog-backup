이전 실험에서는 Zeroth 데이터를 고의로 변조시킨 후 각 환경에서 노이즈에 대한 CER 지표를 확인하는 실험을 하였다. 오늘은 실환경 데이터로 외부 타당도를 검증해보려 한다.

사용 데이터: AI_HUB의 회의 음성 데이터(KconfSpeech Validation D23). 우선 학습을 하지 않고 테스트하기 위해서 Validation 세트 중 한 데이터(D23)를 다운받았다.

## KconfSpeech Validation D23 데이터 분석

### 폴더 구조

```
kconf_valid_d23/
├── wav/D23/G02/
│   ├── S000010/  000000.wav ~ 000464.wav
│   └── ... (총 10개 세션)
└── label/D23/G02/
    ├── S000010/  000000.txt ~ S000010.json
    └── ...
```

### 라벨 포맷

- 케이스 1 - 기본: `n/ 성행위뿐 아니라...` → n/ 제거
- 케이스 2 - 숫자 이형태: `n/ (5000여 명)/(오천 여 명)` → 한글형(뒤) 사용
- 케이스 3 - 빈 파일: 묵음/무발화 구간, skip 처리 필요

### 규모

Zeroth-Korean N=300 대비 15배 규모. 16kHz mono PCM_16 — Gemma 입력 조건 그대로 호환.

## 실험 결과

### 1. N=300 CER/WER

- 평균 CER: **0.433**
- 평균 WER: **0.597**
- Zeroth 데이터: CER=0.089, WER=0.321
- → CER이 5배 정도 높아짐 → 회의 환경이 훨씬 ASR이 어렵다는 것이 수치적으로 검증

### 2. 7명 화자별 CER

speaker 7 CER 0.902 → 극단값 조사 필요

### 3. 환각 현상 + 프롬포트 누출 발생

케이스 1 (심각한 환각):
- ref: "구십" (두 글자)
- hyp: "고시프를 듣고 있으면 너무 몰입하게 되어서..." (완전 창작)
- CER 19.5 — 짧은 발화에 긴 환각이 붙어서 폭발

케이스 2, 3 (프롬프트 누출):
- hyp 끝에 "다음 음성을 한국어로 전사해주세요."가 그대로 출력됨
- 모델이 생성을 멈추지 못하고 프롬프트 텍스트까지 뱉어버린 것

### 4. speaker 7 재측정 (CER > 1.0 제외)

- CER > 1.0 제외 평균: 0.302
- CER > 1.0 딱 1개("구십" 환각 케이스)가 평균을 0.302 → 0.902로 끌어올린 것
