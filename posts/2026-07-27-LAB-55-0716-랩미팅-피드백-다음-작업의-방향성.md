## 1. 지난 랩미팅(07/16) 피드백

```
지난 랩미팅의 주 방향성은 오디오 모듈을 설계한 것이었다.
오디오 모듈의 구조는 wav 파일을 입력 받아서 음향 벡터를 뱉는 것이며
내가 생각한 오디오 모듈의 역할은 감정 분류를 하는 것이 아닌 최대한 텍스트에 포함되어 있지 않은 오디오에 대한 정보를 제공하는 방향으로 생각했다.

이에 대해서 교수님은 "방향성이 좋고 음성 -> 텍스트 변환에 매달리지 말고 텍스트에 없는 음향 정보를 꺼내서 넘겨주는 쪽으로 잘 잡았다"라고 하셨다.
```

## 2. 다음 작업 방향성에 대한 고민

### 오디오 모듈이 뱉는 벡터, 진짜 쓸모가 있을까?

지난 실험에서 알아낸 것은***음향 벡터를 넣으면 LLM 답이 바뀐다.***  

하지만 그 바뀐 답이 맞는 답인지는 정답지가 없어서 재지 못해 확신하지 못합니다.

### 그럼 뭘로 맞는지 채점하지?

어조는 정답 라벨이 없다. -> 내가 사용하는 데이터셋인 감정 음성 데이터셋엔 감정 라벨이 존재

> 감정 라벨을 정답을 맞히는 목표가 아니라 정보가 늘었는지 재는 줄자로 사용하자

- 텍스트만 주면 감정 몇 개 맞히나
- 텍스트 + 벡터 주면 감정 몇 개 맞히나
- 이 차이(델타) = 벡터가 넘겨준 정보의 양

즉, 감정을 맞히는 게 목표가 아니라, 감정을 줄자로만 사용하는 것이다.

### 그래서 이번에 할 것은

```
우선, 텍스트만 줬을 때 vs 텍스트 + 벡터 줬을 때, LLM이 감정을 얼마나 잘 맞히는지 그 차이를 재보도록 하겠다
- 델타 크게 나옴 -> 벡터에 정보 있음 확정 -> 다음 단계
- 델타 안 나옴 -> 벡터부터 다시
```

### 벡터 검증 후 다음 작업

이전 실험까지는 126개 숫자를 말로 풀어서 프롬포트에 입력  

하지만 이번에는 126개 숫자를 그대로 LLM 속에 넣는 것

```
126개 숫자를 LLM이 그대로 받지 못하니 번역기가 필요
[126개 숫자] → 통로(번역기) → LLM이 알아먹는 토큰 → LLM

이 통로 = 투영 레이어(projection layer)
-> 초기 상태: 아무렇게 초기화된 상태라 번역을 제대로 못 함
-> 훈련 필요
```
