## 1. 채점표 설계

```
벡터가 정보를 얹었나를 확인해야하는데 내가 오디오 모듈을 통해 재고 싶은 것은 어조
-> 어조는 정답 라벨이 존재하지 않음

그래서 모듈의 역할이 '감정 맞히기'가 아닌 '정보 넘기기'라면 
채점 대상도 '정답을 맞혔나'가 아닌 넣었더니 '정보가 늘었나(델타)?'

- 텍스트만 -> 감정 몇 개 맞히나 (벡터 X)
- 텍스트 + 벡터 -> 감정 몇 개 맞히나 (백터 존재)
- 차이: 벡터가 넘긴 정보의 양

설계 결정)
1. 판단 불가 선택지 제외
- 감정 15종 중 강제 선택 -> 델타가 과장 없이 보수적으로 잡히게

2. 프레이밍
- 정답률 70% 달성이 아니라 벡터가 N%p 얹었다
-> 감정 분류로 오해받지 않게

3. 감정 못 맞혀도 실패 아님
- 최종 판단은 심박, 표정 등 멀티 모달 데이터를 모아서 판단
- 오디오는 단서를 얹는 역할
```

## 3. 통계 검정 (150 발화)

```
[ 왜 검정이 필요했나 ]
- 델타 +4.0%p는 정답 발화 6개 차이(25 -> 31)에 불과
- 150발화 중 6개는 우연으로도 나올 수 있는 크기
- "+4%p니까 효과 있다"는 과장 -> 통계로 확인 필요

[ McNemar 검정 ]
- 같은 발화를 A/C로 짝지어 정오 변화를 2x2로 분해
- 핵심: 음향이 살림(A틀->C맞) vs 음향이 죽임(A맞->C틀)의 불균형
- 양쪽 다 맞거나 다 틀린 발화는 델타에 영향 없어 제외
```

#### 결과)

![](https://velog.velcdn.com/images/xorms/post/48045a15-310c-4bca-bf2f-9080efbbd770/image.png)

```
MVP의 델타 +4.0%p가 실제 효과인지 표본 변동인지 판단하기 위해
같은 발화를 A/C로 짝지어 정오 변화를 분해하고 McNemar 검정을 적용

150 발화 -> A맞 C맞(유지) 22개, A틀 C맞(음향 살림) 9개, A맞 C틀(음향 죽임) 3개, A틀 C틀(둘 다 실패) 116개

A맞 C맞(22개): 텍스트만으로도 맞고, 음향 줘도 맞음
A틀 C맞(9개): 텍스트만으로는 틀렸는데, 음향 주니 맞음 = 음향이 살림
A맞 C틀(3개): 텍스트만으로는 맞았는데, 음향 주니 틀림 = 음향이 죽임
A틀 C틀(116개): 텍스트도 음향도 다 틀림

궁금한 건 "음향을 넣어서 뭐가 달라졌나"
- 위 네 개 중 두 개(22+116)는 음향을 넣든 안 넣든 결과가 같음
- 음향이 실제로 뭔가 바꾼건 12개
-> 델타 +4%: 이 12개 안의 9:3

이 수치를 숫자로 계산하면 p = 0.146
즉, 방향은 +지만 표본이 작아서 효과의 존재를 확정할 수 없음
-> 발화를 늘려서 다시 확인 필요
```

```
[ 뜻하지 않는 것 (중요) ]
"벡터가 쓸모없다"가 아님
- 이 실험은 벡터 자체 문제인지, 전달 방식 문제인지 구분 못 함
- 다른 증거는 벡터에 정보 있음을 지지:
  · 감정분류 probe 0.229 (랜덤 0.067의 3.4배)
  · 화자 probe 0.958 -> 0.026 (화자 정보 제거)
  · A!=C 31.7% 일관 (반응은 함)
-> "정보는 있으나(probe), 프롬프트로는 못 꺼낸다(델타)" = 전달 방식 문제

[ 핵심 교훈 ]
소표본이 만든 착시를 표본 확대가 걷어냈다
- 150개에서 멈췄으면 "+4%p, 검증 완료"로 잘못 결론
- 갈래 2에서 성능 안 나올 때 "벡터냐 통로냐" 영영 구분 못 했을 것
- 표본 확대 판단이 그 함정을 막음
-> 과장 금지 + verify-first 원칙의 실증
```

## 6. 다음 작업

```
본 작업(갈래 1)은 오디오 모듈이 제공한 음향 벡터를 
프롬프트 경로로 LLM에 전달했을 때 그 정보가 판단에 유효하게 반영되는지를, 
감정 라벨을 정답이 아닌 정보 증분(델타)의 줄자로 삼아 검증한 것이다. 

작은 표본(150발화)에서는 델타 +4.0%p로 음향이 정보를 얹는 듯 보였으나, 
표본을 5배로 확대(750발화)하자 델타가 −1.3%p로 뒤집혔고 통계 검정(McNemar p=0.295)과 감정별 분해 모두에서 유효한 효과가 확인되지 않았다. 

즉 소표본의 양의 신호는 착시였으며, 프롬프트 경로로는 음향 정보가 LLM에 전달되지 않는다는 것이 본 작업의 결론이다. 

다만 이는 벡터가 무의미하다는 뜻이 아니라 전달 경로의 한계로, 벡터 안에 정보가 존재한다는 것은 probe(감정 0.229, 화자 제거 0.026)로 이미 확인되어 있고,
ASR 트랙에서는 동일한 정보를 프롬프트가 아닌 임베딩 경로로 넣었을 때 LLM이 반응함을(오디오 상관 0.128→0.755) 이미 확인한 바 있다. 

따라서 "프롬프트는 막혔다(본 작업) + 정보는 실재한다(probe) + 임베딩은 반응한다(ASR)"라는 세 근거가 합쳐져, 
다음 작업은 자연어 변환 없이 음향 벡터를 임베딩 수준에서 직접 텍스트와 결합하는 표현 수준 융합으로 가는 것이 자연스러운 방향으로 확립된다.
```
