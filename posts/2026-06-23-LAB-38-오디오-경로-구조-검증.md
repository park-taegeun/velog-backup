- 짧은 발화 = 가능도가 약함(오디오 정보량 적음)
-> 사후 분포가 사전 분포(prior)에 지배됨 = 환각
- 이전 실험이 입증: 짧은 발화에서 오디오-출력 상관 0.13(가능도 약함), 모델은 "그렇죠" 같은 대화제 prior로 회피(사전 분포 지배)

#### 인사이트: QLoRA가 베이즈 구조의 어디를 건드렸나?

```
이전 실험에서 한 language_model 어텐션 LoRA는 사전분포 P(전사문)을 손 본 것
즉, 대화체 말투를 KconfSpeech 쪽으로 조정한 것 == prior를 다른 prior로 바꾼 것
-> 가능도 자체는 건드리지 않음

그 결과로 motivated reasoning에 무력화된다. "prior를 조정하는 개입은 prior 지배 문제를 풀 지 못한다."
```

그래서 오디오 정보를 극대화하기 위해서는 **가능도 P(오디오 | 전사문) 채널을 강화**해야 한다.

### 오디오 정보 극대화 방향 2가지

#### 1. 가능도 자체를 키우기 (오디오 인코딩 개선)

- 동결했던 audio_tower를 LoRA로 풀어서, 오디오에서 더 풍부한 특징을 뽑게 함
- 짧은 발화에서도 가능도가 덜 약해지도록 = 오디오 정보량 짜내기
- 베이즈로: P(오디오|전사문)의 변별력 높임

#### 2. 가능도와 사전분포의 결합 지점을 조정 (융합)

- 오디오 특징이 language_model에 들어가는 접점(projection/cross-attention)을 강화
- "오디오가 약해도 그 약한 신호를 prior가 덮어쓰지 못하게" 결합 가중치를 조정
- 베이즈로: 사후 계산에서 가능도 항의 영향력을 키우는 것에 가까움

---

두 방식 중 하나를 선택하기 위해 구조 검증을 먼저 해볼 것이다.

## 구조 검증

### 1. audio_tower

```
[ 전체 구조 ]
gemma-4-E4B-it (전체 모델)
├─ vision_tower    이미지 처리 (우리 안 씀)
├─ audio_tower     소리 처리 ← 방금 본 거 (12층 conformer)
└─ language_model  글자 생성 (nb18까지 우리가 LoRA 건드린 곳, 42층)
```

#### audio_tower 구조 )

![](https://velog.velcdn.com/images/xorms/post/72b979a0-6a3a-4004-95ce-0ef3451193b1/image.png)

1. 오디오가 들어와서 거치는 길

```
오디오 (소리 파형)
   ↓
① subsample      "소리가 너무 길어 → 짧게 압축"
   ↓
② rel_pos_enc    "몇 번째 소리인지 순서표 붙이기"
   ↓
③ layers (12층)  ★여기가 진짜 일하는 곳★
   ↓              "소리에서 의미있는 특징 뽑기"
④ output_proj    "정리해서 내보내기"
   ↓
   글자 생성부로 전달
```

1. layers 한 층 안을 들여다보면

```
들어온 소리
   ↓
[FFN1]      한 번 주무르기
   ↓
[self_attn] "소리들끼리 서로 참고하기" ← 중요
   ↓
[conv]      "옆에 붙은 소리랑 비교하기"
   ↓
[FFN2]      한 번 더 주무르기
   ↓
다음 층으로
```

1. self_attn 안을 보면

```
self_attn
 ├─ q  ┐
 ├─ k  ├─ "소리들끼리 서로 얼마나 관련있나" 계산
 ├─ v  ┘
 └─ post  결과 정리

-> 이 q/k/v/post가 LoRA로 학습시킬 실제 타겟
```

### 가능도와 사전 분포의 결합 지점 구조 )

오디오 특징이 language_model에 들어가는 접점을 살펴보았다.
audio_tower라는 **오디오 처리부**와 **글자 생성부**는 사용하는 차원이 다르기 때문에 이 둘을 연결짓는 번역기 역할이 필요하다.

- 오디오 처리부: 1536차원으로 말함 (오디오 전용 표현)
- 글자 생성부: 2560차원으로 알아들음 (텍스트 언어)

이렇게 차원이 맞지 않으니 번역기가 1536 -> 2560으로 변환해줘야 글자 생성부가 알아듣는다.
-> 해당 번역기 이름이 *embed_audio(정확히는 그 안의 embedding_projection)*

#### 전체 흐름

```
소리
  ↓
[오디오 처리부 12층]   소리에서 특징 뽑기 (audio_tower 영역)
  ↓  1536차원으로 결과 나옴
[embed_audio = 번역 다리]   1536 → 2560 변환  <- 결합 영역
  ↓  이제 글자 생성부가 알아듣는 언어
[글자 생성부 42층]   한국어로 받아쓰기
  ↓
"안녕하세요"
```

#### 결합 영역을 학습시키면 뭐가 달라지나?

지금 문제: 짧은 발화에서 오디오 신호가 약하면 글자 생성부가 "에이 소리 잘 안 들리네, 그냥 내가 써야지"하고 오디오를 무시하는 현상

결합 영역을 학습시키면 "약한 오디오라도 좀 더 또렷하게 강하게 번역해서 넘겨" -> 글자 생성부가 무시하기 어려워짐

![](https://velog.velcdn.com/images/xorms/post/bb0ef540-5774-48cd-aaea-7b1d065876f3/image.png)

- 보라(audio_tower) = A 영역, 소리 특징 뽑기
- 파랑(output_proj) = 1024→1536, audio_tower 마지막 출력
- 초록 박스(embed_audio) = ★결합 영역★, 번역 다리.
- 안에 정규화(청록) → 번역기(빨강, 진짜 타겟) 순서
- 회색(language_model) = nb18 건드린 곳, 받아쓰기

## 다음 작업 결정

다음과 같은 이유로 다음 작업으로는 먼저 결합 영역을 강화하기로 했다.

### 1. 판정 지표가 가리킴

- 핵심 지표가 오디오가 출력에 영향을 미치는가
-> 결합 영역은 오디오가 LLM에 들어가는 그 지점을 건드림

### 2. 결합 영역의 강화가 오디오 타워 강화의 진단 도구

- 결합영역만 강화했는데 상관계수 오름 → "문제는 인코딩이 아니라 전달이었다" 증명. 오디오타워 강화 불필요.
- 결합영역 강화해도 안 오름 → "전달 통로는 멀쩡한데 인코딩이 약하다" → 그제서야 오디오타워로 갈 근거가 생김.
