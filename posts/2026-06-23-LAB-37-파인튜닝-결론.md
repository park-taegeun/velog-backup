이전 Fine-tunning 학습을 통해서 얻은 결론은 이렇다

> finetuned의 짧은 발화 CER 개선은 "오디오를 더 들어서"가 아니라, base가 길게 뱉던 환각성 과생성을 억제한 부산물이다.
> 게다가 그 억제가 과해서 정답 내용까지 절단하고 대화체 상투어로 회피하는 부작용이 있다.

내가 실험을 통해 원한 것 (오디오 기반 길이 조절)

- 오디오 들음 -> "아 이 발화 짧네" -> 그 길이만큼 정확히 전사
-> 오디오 신호가 출력 길이를 결정 (짧으면 짧게, 길면 길게, 내용은 다 맞추면서)

실제 일어난 것 (무차별 길이 억제)

- 오디오 안 듣고 -> "무조건 짧게 뱉어" -> 정답이 길든 짧든 잘라버림
-> 오디오랑 무관하게 그냥 출력을 짧게 만드는 prior(사전분포) 학습

```
language_model attention만 LoRA로 건드렸더니
모델이 오디오를 더 듣는 길(어려운 길) 대신 텍스트 prior로 "짧게 뱉기"라는 꼼수를 찾아냄(쉬운 길)
-> "motivated reasoning"
	- 모델이 loss를 줄이는 가장 쉬운 경로를 택한 것(오디오 이해가 아닌 출력 절제)
```

---

## 실험

### 1. 배경

짧은 발화의 CER 개선이 "오디오 기반 길이 조절"인지 "오디오 무관 무차별 억제"인지 못 박기 위해 오디오 길이와 출력 길이의 상관을 정답/base/finetuned로 비교

### 2. 실험 결과

![](https://velog.velcdn.com/images/xorms/post/60c9d921-95ef-47c4-ab41-4f6c4d3baf27/image.png)

- 진짜 오디오 조건화면 finetuned가 정답(0.74)에 근접해야 하나 0.13에 그침
-> base(0.02)보다 약하게 올랐을 뿐 정답과 큰 격차
- 출력 상당수가 오디오 길이와 무관하게 최소 길이 상투어("그렇죠")로 수렴 -> 부분적 오디오 반응은 있으나 지배적인 것은 텍스트 prior 회피

즉, language_model 어텐션 LoRA로는 충분한 오디오 조건화 미달

### 3. 결과 해석

![](https://velog.velcdn.com/images/xorms/post/2772bc6d-434a-4440-a831-90e8e87d365c/image.png)

#### 그래프 읽는 법 )

```
  x축 = 입력 오디오 길이(초), y축 = 모델이 생성한 출력 길이(글자 수).
  점 하나 = 발화 하나. 
  
  빨간 추세선 = x-y 선형 회귀선(기울기가 가파를수록 오디오 길이에 따라 출력 길이가 비례해 늘어남 = 오디오 조건화 강함).
  Pearson r = 두 길이의 선형 상관(1에 가까울수록 강한 비례, 0이면 무관).
  
  핵심 논리: 모델이 오디오를 제대로 들으면 "긴 오디오 -> 긴 출력"이 성립해 추세선이 가파르고 r이 높아야 함. 
  정답(ref)이 그 이상적 기준.
```

#### 패널별 관찰 )

정답(ref, r=0.739)

- 점이 우상향 집중, 추세선 가파름.
- 오디오 길수록 정답 길이도 김(정상 조건화 기준선).

base(r=0.024)

- 추세선 거의 수평. 출력이 위쪽에 넓게 퍼져
- 오디오 길이와 무관하게 과생성(환각).

finetuned(r=0.128)

- 추세선은 우상향이나, y=4 부근(상투어 "그렇죠"등 최소 길이 출력)에 점이 오디오 전 구간 걸쳐
깔림
-> 이 바닥 점들이 상관을 낮춤.

#### 해석 )

finetuned는 두 부류로 갈림:
(1) 오디오 길이를 부분적으로 따라가는 점들(추세선 형성)
(2) 오디오 무관하게 바닥(4자 상투어)에 깔린 점들 -> 상관 0.13으로 저하

> 전면적 무차별 억제가 아니라 "부분적 오디오 반응 + 상당수 상투어 회피"의 혼재.
> base보다 약간 개선(0.02->0.13)됐으나 정답(0.74)에 크게 미달.

즉, language_model 어텐션 LoRA는 부분적 오디오 반응을 만들었으나 충분한 오디오 조건화에는 도달 못 함
모델은 어려운 구간에서 오디오를 더 듣는 대신 텍스트 prior(최소 길이 상투어)로 회피
-> 표면 레벨 통합의 한계, **오디오 경로(audio_tower / 표현 융합) 개입이 필요할 거 같음**
