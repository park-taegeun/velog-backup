# "분석을 멈출 줄도 알아야 한다" — 14개 영역 순회를 끝내며

> Claude Code 조사 2건으로 핵심 리스크를 해소하고 나서, 시스템 전체를 한 번 훑겠다고 시작한 14개 영역 순회가 중간에 방향을 바꿨다.

---

## 14개 영역 순회를 시작했던 이유

4/29 중간 발표 후 굵직한 결정들이 줄지어 있었다. A-1+A-3 통합 컨셉이 정해졌고, 시스템 설계도 1차/2차 분리로 재설계가 필요했다. 일정을 새로 짜야 했고, 부품 발주 결정도 필요했고, 리스크 관리 계획도 정리해야 했다.

"이 시점에서 한 번 시스템 전체를 다 훑고 가야 한다"는 판단으로 14개 영역을 정의했는데, 1~4번까지는 진짜 굵직한 결정들이었다. 5초 알림 목표 재검토, 1차/2차 분리 재설계, 일정·발주, 리스크 관리. Claude Code 조사 2건으로 카메라+마이크 동시 동작과 서버 스펙, STT, 카카오 이미지 첨부까지 핵심 리스크도 해소됐고.

---

## 5번 영역에서 멈춰선 순간

1~4번이 끝나고 5번 "데이터 흐름/네트워크"로 넘어갔는데, 들어가자마자 뭔가 이상했다.

"ESP32에서 사진+오디오 multipart로 어떻게 보낼지", "1차 POST와 2차 POST를 어떻게 분리할지", "Wi-Fi 업로드 시간 추정" 같은 질문들이 줄줄이 나왔는데 이거 다 책상에서 정할 수 있는 게 아니었다. 펌웨어 짜면서 실측해야 답 나오는 항목들이 대부분이었다.

그래서 잠깐 멈추고 생각해봤다. "내가 지금 뭘 하고 있는 거지?"

---

## "지금 결정 vs 개발 중 결정"의 경계

한 발 물러서서 보니 14개 영역에서 다뤄야 할 항목들이 두 부류로 나뉘었다.

**지금 결정해야 할 것**: 시스템 구조 자체에 영향을 주는 결정, API 인터페이스 계약, DB 스키마, 인프라 선택 등

**개발 중에 실측해야 할 것**: 임계값, 녹음 길이, 메모리 footprint, 응답 시간 같은 수치들

1~4번이 깊이 다뤄진 이유는 전부 첫 번째 부류였기 때문이었다. 그런데 5번 이후로 넘어가서 이론적으로 다 파헤치려 한 게 잘못된 접근이었다. 책상에서 정할 수 없는 걸 책상에서 정하려고 시간을 쓰고 있었던 거였다.

---

## 결정: 5~14번은 "방향만 잡고" 종료

그래서 나머지 영역들은 가볍게 한 번 훑고 마무리했다.

- **5번 데이터 흐름**: 1차/2차 POST 분리 유지, 디테일은 펌웨어 짤 때
- **6번 서버**: t3.small + Gunicorn 워커 2개 + preload_app=True, 메모리 실측은 PoC
- **7번 카카오톡 API**: "나에게 보내기" + 이미지 업로드 API, 토큰 갱신은 APScheduler 패턴
- **9번 프론트엔드**: React + Vite + shadcn/ui, 글자 18px+, WCAG AA 대비
- **10번 데이터 저장**: SQLite 4개 테이블, 이미지 30일 보관, 카카오 CDN
- **11번 ML 데이터**: 9단계에서 이미 확정
- **12번 인용 논문**: 4편 + rtzr 벤치마크 추가
- **13번 테스트**: 4번의 마일스톤 체크가 사실상 테스트
- **14번 보안**: 졸작 시연 전제로 한 슬라이드 명시
- **8번 발표/시연 콘텐츠**: 유일하게 미진행 — 5월 중 글로 따로 정리하기로

---

## 그래도 한 가지는 짚고 갔다 — ToF 정책 분기

5번 영역을 가볍게 훑던 중 설계 결함 하나를 발견했는데, 이건 그냥 넘어갈 수가 없었다.

기존 흐름은 "ESP32에서 사람 없으면 서버 전송 차단"이었는데, 화재경보는 사람이 누른 게 아니라 자동으로 울리는 거였다. 사람 없을 때 화재경보가 누락되는 리스크가 있었다.

그래서 ToF 결과를 차단 조건이 아니라 메타데이터로 서버에 첨부하고, 서버에서 클래스별로 정책을 분기하는 방식으로 바꿨다.

```
소리 감지 → YAMNet 분류 → ToF 메타데이터 첨부
                                    ↓
                        서버에서 클래스별 분기
                        ├─ 화재경보 → ToF 우회 (무조건 진행)
                        ├─ 노크    → ToF 사람 검증
                        └─ 초인종  → ToF 사람 검증 + (등록 시) SP/DTW
```

추가로 ToF 상시 ON, 음향 트리거는 단순 RMS 임계값, 카메라 캡처는 멀티코어 병렬 처리도 함께 결정됐다.

---

## 얻은 교훈

졸작에서 가장 흔한 함정 중 하나가 "분석 마비"다. 시스템을 완벽하게 설계하고 싶은 욕심에 책상에서만 시간을 쓰다가 정작 본 개발 시간이 부족해지는 패턴인데, 이번에 그 경계를 거의 밟을 뻔했다.

14개 영역 중 진짜 큰 결정이 필요했던 건 1~4번 그리고 5번에서 발견한 ToF 분기까지였고, 나머지는 본 개발을 진행하면서 자연스럽게 채워질 디테일들이었다. 큰 결정이 끝났으면 미완성 상태에서도 손을 움직여야 한다는 걸 다시 배운 셈이었다.

"분석을 멈출 줄도 알아야 한다"는 게 이번 회고의 핵심이었다.
