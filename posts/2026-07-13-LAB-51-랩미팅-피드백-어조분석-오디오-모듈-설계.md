## 랩미팅 피드백

10일에 교수님과의 랩미팅이 끝나고 내가 든 고민은 이렇다.

```
어차피 Text가 존재하고 본 연구가 오디오 데이터만 사용해서 감정을 분류하는 것이 아닌,
멀티 모달 데이터로 감정을 분류하는 것이다.

그래서 Audio에서는 오디오에서만 추출할 수 있는 음향 정보(MFCC 및 피치)를 추출해서
텍스트에 정보를 붙여주는 느낌으로만 가면 되지 않을까??

그 음향 정보를 통해 어조 분석까지만 가면 되려나?
굳이 감정 분류를 오디오 선에서 하는게 아닌 거 같은 느낌

-> 오디오 섹션의 역할은 텍스트엔 없고 오디오에만 있는 정보를 추출해서 잘 전달하는 것
```

### 어조 분석

- 어조 = 해당 화자의 평상시 발화 대비, 이 발화가 벗어난 방향과 크기 (상대적 편차)

---

## 모듈 설계

### 1. 모듈의 역할

```
wav 입력  →  [오디오 모듈]  →  숫자 벡터  →  모듈 통합(융합)
                                              ↑ 여기서 판단
```

- 감정 분류 안 함
- 오디오는 최대한 오디오에 대한 정보를 제공하는 방향
- 음성 데이터 변화량 추출 -> 어조 분석 -> 모듈 통합

### 2. 출력 구조

wav 파일 하나를 열면 프레임으로 쪼개짐  

여기서 음성 신호를 25ms 단위의 프레임별로 쪼갠다.

#### 25ms

- 음소 하나가 대략 50~150ms 지속
- 창이 그보다 길면 여러 음소가 한 창에 섞여 들어가기 때문에 뭉개짐
- 피치를 재려면 성대 진동 주기가 창 안에 최소 2~3번은 들어와야 함
- 남성 저음 주기는 대략 11.8ms
- 2주기를 담으려면 최소 24ms 필요

#### 이동 폭 (hop) 10ms

- 창을 25ms씩 자르는데 얼마나 밀면서 자를 거냐
- 25ms씩 밀면 창 경계에서 정보가 끊기게 됨

```
[--창1--][--창2--][--창3--]
```

- 10ms씩 밀면 변화가 부드럽게 추적 + 창끼리 15ms 겹침

```
[----창1----]
     [----창2----]
          [----창3----]
     ↑10ms↑
```

- delta(변화량) 계산이 가능해짐
- 사람의 조음 기관(혀, 입술)이 움직이는 속도가 대략 이 스케일

프레임마다 2가지를 계산 -> 피치, MFCC

그러면 발화 하나가 이렇게 생긴 표가 된다.

```
프레임1  프레임2  프레임3  ...  프레임500
F0        180     185     190          260
MFCC c1   -3.0    -3.1    -3.5         -4.3
MFCC c2    1.2     1.3     1.1          0.8
...
MFCC c13   0.4     0.4     0.5          0.2
```

이 표를 어떻게 요약해서 넘길 것인가? = 출력 구조

#### 시선 1: 정적 (값 자체)

표의 각 줄을 가로로 평균을 냄  

MFCC와 피치 둘 다 -> 결과: "이 발화는 평균 피치는 ~Hz이고 음색은 대략 이랬다"

#### 시선 2: 동적 (값의 변화)

정적을 바라보는 시선에서는 평균값만 보기 때문에 발화의 움직임을 체크하지 못 한다.  

그래서 피치 기울기와 MFCC delta를 재서 움직임을 기록한다.

- 피치 기울기: F0 줄에 직선을 그어서 기울기를 잼
- MFCC delta

이 두 가지 시선이 층1 (이 발화의 실제 물리값)  

층2는 그 사람 기준으로 즉, baseline 편차

#### 층2: 편차

```
편차 = (이 발화 값 − 이 화자 평소) / 이 화자 표준편차
```

층1에서 구한 원본값들에 전부 z-score를 구해서 편차를 구해서 어조분석값을 구한다.

```
[음성 데이터 변화량 추출]  →  [어조 분석]  →  [모듈 통합]
      원본 (정적+동적)         편차            융합
```

## 데이터 선정

데이터는 KconfSpeech(한국어 회의 음성)를 사용하기로 했다.  

설계한 모듈이 요구하는 전제조건이 이 데이터에 모두 존재하기 때문이다.

- 발화 단위로 잘린 wav (벡터 1개 = 발화 1개)
- 화자 ID (baseline 계산의 필수 조건) - 세션 json의 dialogs[].speaker에 발화별로 존재
- 세션 구분 (baseline 산출 단위) - 10개 세션
- 감정 라벨은 불필요. 이번 모듈은 라벨을 쓰지 않는다.

실측 결과 valid D23 기준 3,588발화(7.06시간), 16kHz mono PCM_16, 화자 셀 71개(세션×화자), 화자별 발화 수 최소 15개.  

F0 추출 신뢰도도 확인했다. 남성 F0 중앙값 147.2Hz, 여성 212.4Hz로 물리적으로 타당한 값이 나온다.

먼저 파이프라인 설계 단계에서 S16 세션을 사용하여 구축하기로 했다.

![](https://velog.velcdn.com/images/xorms/post/c8cf832f-1854-4d74-a1cd-ca6f1c00b0a4/image.png)

이유는 전 세션 중 화자(10명)와 발화 수(623개)가 가장 많다.  

또한 화자별 발화 수 격차가 가장 크다(15개~144개, 9.6배).  

baseline은 발화 수가 많을수록 안정적인데, 한 세션 안에서 발화가 많은 화자와 적은 화자가 같이 있어야  

발화 수가 baseline 신뢰도에 얼마나 영향을 주는가를 볼 수 있을 거라 생각한다.

S000010은 F0 진단에서 남성 화자 F0 중앙값이 91.9Hz로 나와  

타 세션(123~178Hz)과 크게 벗어나 첫 구축용에서는 배제했다.

baseline이 세션 내에서 완결되는 구조이므로 세션 1개로도 모듈이 완결되며,  

이후 전체로 확장할 때 재작업이 발생하지 않는다.  

실제 실험 데이터로는 KconfSpeech 전체(10세션, 3588발화)를 사용할 예정이다.
