## 1. Gemma 4 내부에서 음성 -> 텍스트 변환이 가능한지

- Whisper 같은 외부 STT 필요 없음
- Gemma 4 E4B가 음성 -> 텍스트 변환을 내부에서 해줌
- 즉, 음성 파일(wav) 파일을 Gemma 4한테 주면 알아서 텍스트로 변환해줌

## 2. MFCC(Mel-Frequency Cepstral Coefficients)

- 비유하자면 음성의 지문과 같음
- 음성은 공기 진동(시간에 따라 변화하는 파동) -> 그대로 컴퓨터에게 주면 너무 복잡함  
  -> 그래서 음성의 핵심 특징만 13~40개 숫자로 뽑는 숫자 묶음을 만듦

> #### 전통 방식: 음성 → MFCC 추출 → 감정 분류 모델 → 감정 라벨
> #### 지금: 음성 → Gemma 4 (내부적으로 알아서 처리) → 감정 라벨

즉, 교수님이 내게 주신 문서를 보면  
*음성데이터에서 MFCC 및 피치 변화량을 추출하여 어조를 분석하고* 라고 적혀 있는데  
MFCC/Pitch 추출은 Gemma 내부에서 자체적으로 가능 -> 어조 자동 분석 실험하면 될 듯이라는 생각을 했다.

## 3. ASR(자동 음성 인식) 공식 프롬포트

조사해보니 Google이 Gemma 4한테 음성 → 텍스트 시킬 때 쓰라고 직접 준 프롬프트 존재하는 것을 알게 되었다.

#### 공식 템플릿

```
Transcribe the following speech segment in {LANGUAGE} into {LANGUAGE} text.

Follow these specific instructions for formatting the answer:
* Only output the transcription, with no newlines.
* When transcribing numbers, write the digits, i.e. write 1.7 and not one point seven, and write 3 instead of three.
```

- 한국어로 ASR을 시키려면 {LANGUAGE} 자리에 Korean 채우면 됨
- 한국어 ASR 성능은 미정 -> 실험 및 연구 대상

조사를 하다 보니 궁금증이 몇 가지 생겼다.  
메모장에 끄적거린 내용을 그대로 옮겨보면,

```
정리해보면,

 ASR(음성 -> 텍스트) ]

- 이 음성에서 텍스트로 변환이 실시간으로 되어야 하는데 변환 방식이 궁금
  -> 한 글자씩 받아서 바로 변환을 하는 건지 (스트리밍 방식)
  -> 아니면 30초처럼 구간별로 변환을 해주는 건지 (배치 방식)

[ 어조 분석 ]
방식 충돌이 발생함
1. 음성 -> MFCC/피치 추출 -> 어조 분류기 -> 감정
2. 음성 -> Gemma 4(내부에서 처리) -> 감정

그래서 
2번 같은 경우는 어느 정도 성능이 나오는지 확인이 필요 -> 1번과 2번 둘 다 해서 ppt로 정리 후 랩미팅 때 말하면 좋을듯?
```

위 생각에 대한 답으로

### Gemma 4의 ASR 방식은 30초 구간별 변환하는 배치 방식

- Gemma 4같은 Transformer 기반 멀티모달 모델은 구조적으로 입력 전체를 한 번에 봐야 attention이 작동
- 30초 음성을 통째로 받아서 1초당 25tokens x 30초 = 750 audio tokens -> 텍스트 생성

그럼 실시간 처리는 어떻게 하지?

- chunking + 짧은 청크로 끊어서 처리함

```
긴 대화 음성
  ↓ 슬라이딩 윈도우 (예: 3초 청크, 1초 overlap)
[0~3초] → Gemma → "안녕하세요"
[2~5초] → Gemma → "오늘 회의는"
[4~7초] → Gemma → "다음 주로 미뤄요"
  ↓ 중복 제거 + 이어붙이기
"안녕하세요 오늘 회의는 다음 주로 미뤄요"
```

- 즉, Gemma 4는 청크 기반 준실시간 방식

## 4. 감정 추론 방식

> - librosa MFCC/피치 -> 분류기
> - Gemma 4 prompt
> - wav2vec2 한국어 감정 모델

wav2vec2는 Meta(구 Facebook)가 만든 음성 전용 모델이다.  
Gemma 4랑 비교해보면, Gemma 4는 raw 음성을 내부처리하여 출력값이 텍스트이고  
wav2vec2는 raw 음성을 내부처리하여 뱉는 출력값이 음성 특징 벡터(음성의 의미를 압축한 표현)이다.  
즉, 이 벡터를 분류기에 통과시키면 감정 라벨이 나오는 방식.

어찌됐든 본 연구에서는 Gemma 4 LLM을 사용해야하기 때문에

```
음성 ─┬→ [Gemma 4] → 텍스트 (ASR)
      └→ [wav2vec2] → 감정 벡터 ─→ [Gemma 4 prompt에 주입] → 최종 판단
                                      ↑ 여기가 통합 지점
```

이 방식으로 위 3가지 방법을 테스트/비교해볼 생각이다.
