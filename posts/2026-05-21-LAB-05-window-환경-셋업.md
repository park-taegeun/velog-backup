## [ 01. 왜 WSL2 + VS Code인가 ]

연구실 데스크탑은 윈도우인데, AI 라이브러리들은 대부분 리눅스 기준으로 작성된다.
그래서 윈도우에서 바로 돌리면 호환성 문제가 자주 생긴다.

해결책은 **WSL2(Windows Subsystem for Linux)**. 윈도우 안에서 진짜 리눅스(Ubuntu)를 돌릴 수 있게 해주는 기능이다. 가상머신보다 가볍고, NVIDIA 드라이버도 윈도우 쪽에만 깔면 WSL이 자동으로 인식한다.

IDE는 **VS Code**로 정했다. PyCharm, Cursor, Antigravity 등 후보가 많았지만 VS Code + WSL 조합이 AI 연구실 표준에 가장 가까웠다. 무료고, 확장이 강력하고, 나중에 연구실 서버에 SSH로 붙을 때도 같은 환경을 쓸 수 있다는 점이 컸다.

전체 그림은 이렇다.

- Windows 11 (베이스)
- WSL2 + Ubuntu 22.04 (실제 작업 환경, git/Python/conda 등 다 여기 안에)
- VS Code (Windows에 설치하고 WSL에 원격 접속)

## [ 02. 셋업 흐름 ]

전체 단계는 크게 이렇다.

1. PowerShell에서 `wsl --install -d Ubuntu-22.04`로 WSL 설치
2. Ubuntu에서 기본 개발 도구 설치(`build-essential git curl wget`)
3. 윈도우에 VS Code 깔고 WSL 확장 설치
4. git 사용자 설정 + SSH 키 생성 후 GitHub에 등록
5. Miniconda 설치, `ai`라는 conda 환경 생성
6. PyTorch 설치 + GPU 인식 테스트
7. 핵심 라이브러리 설치
8. Jupyter 커널 등록 후 VS Code에서 노트북 실행

하나씩 짚어가면 별 거 아닌데, 모르고 시작하면 어디서 막힐지 모른다.
특히 6번에서 잘못 깔면 GPU가 안 잡혀서 며칠 헤맬 수도 있는 부분이 있었다.

## [ 03. RTX 5070(Blackwell)의 함정 ]

여기서 가장 많이 헤맬 뻔했다. RTX 5070은 NVIDIA의 최신 **Blackwell 아키텍처(compute capability sm_120)**를 쓰는데, PyTorch 공식 페이지에서 기본으로 안내하는 명령어는 CUDA 12.1이나 12.6 빌드라서 sm_120과 호환되지 않는다.

그냥 `pip install torch` 하면 이런 에러를 만난다.

```
NVIDIA GeForce RTX 5070 with CUDA capability sm_120 is not compatible with the current PyTorch installation. The current PyTorch install supports CUDA capabilities sm_50 sm_60 sm_70 sm_75 sm_80 sm_86 sm_90.
```

해결책은 **CUDA 12.8 빌드를 명시적으로 설치**하는 것.

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
```

핵심은 `--index-url ...cu128` 부분. 이게 있어야 sm_120을 지원하는 PyTorch 2.11.0+cu128이 받아진다.

설치 후 테스트해보니,

```
PyTorch: 2.11.0+cu128
CUDA available: True
GPU: NVIDIA GeForce RTX 5070
Compute capability: (12, 0)
```

`CUDA available: True`가 뜨는 순간 좀 짜릿했다. 검색해보면 이 부분에서 며칠씩 헤매는 사람도 많다고 하는데, 한 번에 통과한 게 운이 좋았다.

## [ 04. 핵심 라이브러리 ]

연구실에서 다루는 멀티모달 AI 연구를 생각하면 결국 다 필요한 것들이다.

- `numpy`, `pandas`, `scikit-learn` — 데이터 처리 기본
- `transformers`, `datasets` — HuggingFace 라이브러리. LLaMA-3 같은 모델 한 줄로 불러옴
- `peft`, `bitsandbytes` — LoRA, 양자화. VRAM 12GB로 큰 모델 돌릴 때 필수
- `timm`, `opencv`, `albumentations` — 비전 쪽
- `wandb` — 실험 추적. 학습 로그를 자동 기록

연구 자료에서 봤던 LLaMA-3, LoRA, RLHF 같은 키워드들이 결국 이 라이브러리 위에서 돌아간다는 걸 알게 됐다.

## [ 05. 이게 코랩이랑 뭐가 다른가? ]

셋업하면서 든 생각. "이거 그냥 코랩이랑 같은 거 아닌가?"

차이는 명확하다.

- **세션이 안 끊긴다.** 코랩은 12시간/90분 idle 제한 때문에 긴 학습이 자주 죽는다
- **내 GPU다.** 코랩 무료는 T4를 받으려고 줄을 서야 한다
- **풀 IDE다.** 코드 100줄 넘으면 코랩은 답이 없다. 디버거, git, 모듈 분리가 자연스럽다
- **데이터/모델이 영구 저장된다**

물론 A100/H100 같은 큰 GPU가 필요하면 결국 클라우드를 써야 한다. 보통 실제 연구자들은 둘 다 쓴다. 로컬에서 개발하고, 큰 학습은 서버에서.

비유하자면 코랩은 카페에서 빌려쓰는 노트북이고, 이건 내 책상의 데스크탑이다. 셋업이 좀 걸려도 한 번 해두면 내 거다.

## [ 06. 셋업하면서 느낀 점 ]

처음엔 막막했다. WSL? CUDA? conda? sm_120? 또 그 "이게 뭔데!?" 상태가 됐다. 그런데 한 단계씩 짚어가다 보니 각각이 왜 필요한지가 보였다.

- 윈도우에 리눅스 환경이 필요해서 → WSL2
- Python 환경을 격리해서 관리하려고 → conda
- GPU로 학습하려고 → CUDA 호환되는 PyTorch
- 빠르게 실험하려고 → Jupyter
- 코드 관리/백업하려고 → git, GitHub

연결되는 흐름이 보이니까 그제서야 "아, 이래서 이렇게 셋업하는구나"가 됐다. 처음부터 큰 그림을 보려고 하지 말고, 일단 한 단계씩 해보고 나중에 돌아보면 그림이 보인다는 것. 공부할 때나 셋업할 때나 비슷한 것 같다.

이제 진짜 시작이다. 지난 글에서 정리한 Pandas, HuggingFace, LoRA를 실제로 써먹을 시간이다.
