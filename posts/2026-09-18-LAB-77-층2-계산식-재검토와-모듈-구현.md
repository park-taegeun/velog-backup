## 무엇이 문제인가

층2의 계산식)
```
층2 = (이번 발화 − 화자 기준점 평균) / 화자 기준점 표준편차
```

평균과 표준편차 **두 가지가 모두 화자별로 필요함**

76번에서 측정한 것은 평균 쪽뿐
4발화면 쓸 만하다는 결론도 평균에 대한 것

표준편차는 통계적으로 평균보다 느리게 수렴함
-> 평균이 쓸 만해지는 지점에서 표준편차도 쓸 만하다는 보장이 없음

게다가 표준편차는 **나눗셈의 분모**
-> 추정이 부정확하면 값이 어긋나는 정도로 끝나지 않고 폭발함

## 표준편차 기준점 측정

평균에 적용한 절차를 그대로 적용
- 그 화자 전체 발화의 표준편차를 정답으로 둠
- 앞 N발화로 만든 표준편차가 얼마나 떨어지는지 측정
- 화자 간 표준편차 거리로 나누어 비율로 환산
- 표준편차는 발화 하나에서 정의되지 않으므로 2발화부터

**결과**

| 발화 수 | 평균 | 표준편차 |
|---|---|---|
| 2발화 | 72% | **234%** |
| 4발화 | 59% | **171%** |
| 7발화 | 54% | **136%** |
| 10발화 | 49% | **117%** |

측정한 모든 구간에서 표준편차 오차가 평균 오차보다 큼

## 표준편차를 쓸 수 없는 이유

10발화까지 밀어도 117%
-> 100%를 넘는다는 것은 **아무 다른 화자의 표준편차를 가져다 쓰는 것보다 나쁘다**는 뜻

**원인**
```
화자 간 표준편차 거리   1.854
화자 간 평균 거리      5.910
```

화자마다 평소 톤의 위치는 뚜렷이 다르지만 발화 안에서의 변동 폭은 서로 비슷함
차이가 작으므로 적은 표본으로는 그 차이를 분해할 수 없음

**결정**
실전 계산식에서 표준편차는 화자별로 두지 않고 전역값을 사용
층1을 만들 때 이미 전역 표준화를 거치므로, 층2는 표준화된 값에서 화자 평균을 빼는 것만으로 성립함

```
층2 = 표준화된 이번 발화 − 화자 평균
```

**부수 효과**
나눗셈이 사라짐
-> 분모가 작아 값이 폭발할 위험이 없어짐
-> 초반 발화에서 예외 처리를 따로 두지 않아도 됨

**이 결정의 성격**
76번의 기준점 분기와 같은 성격
실험에서는 화자별 표준편차를 쓸 수 있었고 실제로 그렇게 측정했으나, 실전에서는 표본이 부족해 성립하지 않음

다만 기존 결과 수치는 화자별 표준편차를 사용한 층2에서 나온 것
전역 표준편차로 바꾸었을 때 같은 수치가 유지되는지는 확인된 바 없음
-> 모듈에서 두 방식을 모두 선택할 수 있게 둠

## 모듈 구현

측정 결과를 코드로 옮길 차례. 문서로만 남으면 산출물이 되지 않음

앞서 분리한 추출기는 발화 하나를 받아 63차를 낼 뿐 화자 기준점을 들고 있지 않음
실시간 대화에서 쓰려면 이전 발화를 기억하는 구조가 필요함

**무엇을 만들었나**
- 발화를 하나씩 받아 126차를 내보내는 모듈
- 화자별로 이전 발화의 층1 벡터를 쌓아두고 기준점이 설 때 층2를 계산
- 호출하는 쪽은 오디오와 화자 식별자만 넘기면 됨
- 대화가 끝나면 초기화를 호출

## 설계 결정과 근거

**전환 시점: 이전 발화 4개**
-> 76번에서 기준점 오차가 4발화 이후 완만해지는 것을 확인

**기준점에 현재 발화를 포함하지 않음**
-> 포함하면 그 발화가 기준점을 자기 쪽으로 끌어당겨 편차가 스스로 줄어듦
-> 기여가 큰 것으로 확인된 구간이 바로 평소에서 벗어난 발화이므로 이 문제가 실제로 걸림

**출력 차원을 항상 126으로 고정**
- 기준점이 서지 않은 구간에서는 층2 자리를 0으로 채움
- 대신 기준점 유효 여부를 함께 넘김

차원을 고정한 이유는 융합단 때문
- 층1 구간에서 63차를 내보내면 받는 쪽이 입력 크기에 따라 분기해야 함
- projection도 두 벌이 필요해짐
- 0으로 채우면 하나로 처리됨

**전역 표준화 통계**
- 층1 63차는 차원별 스케일 차이가 1000배에 이름 (std 0.101~103.5)
- 기존 실험은 학습 split에서 산출했으나 그 값도 소실됨
- 재추출한 21,564발화 전체에서 새로 산출해 모듈과 함께 저장
- 화자별이 아니라 단일 값이므로 층1의 화자 정보는 보존됨

## 검증

실제 데이터 전체에 적용)
- 층2가 켜지는 비율 **40.7%**. 한 대화에서 한 화자의 발화가 중앙 7개이고 그중 앞 3개가 꺼지므로 예상과 일치
- 층2 값의 절대값 중앙 **0.515**. 층1보다 작음. 같은 화자가 같은 대화에서 비슷한 톤으로 말하므로 평소 대비 편차가 작게 나오는 것이 정상
- 차원별 표준편차 **0.569~1.236**. 63차 전 구간에서 값이 살아 있으며 죽은 차원이 없음

## 실시간 지연

배치 처리만 해왔으므로 발화 단위 지연이 측정된 적이 없었음
미해결 항목으로 남아 있던 것을 이번에 확인

**결과**
```
발화 1초당 처리   57ms
실시간 대비      5.7%   (말하는 속도의 약 17배)
발화당 중앙      198ms
```

발화 길이 0.6초에서 18초까지 전 구간에서 비율이 일정함
길이에 따라 급격히 느려지는 구간은 없음

발화가 끝난 뒤 벡터가 나올 때까지의 지연은 3초 발화 기준 170ms 수준

**한계**
발화가 끝나야 처리가 시작됨
63차가 발화 전체의 평균, 표준편차, 기울기이므로 발화 도중에는 계산이 성립하지 않음
-> 속도의 문제가 아니라 특징 설계상의 제약
-> 발화 중간에 어조를 내보내려면 특징 구성을 다시 잡아야 함

## 결론

층2 계산식에서 표준편차를 화자별로 둘 수 없다는 것을 확인했다
10발화까지 밀어도 남의 것을 쓰는 것보다 나쁘다
화자마다 평소 톤의 위치는 뚜렷이 다르지만 발화 안에서의 변동 폭은 서로 비슷하기 때문이다

그래서 실전 계산식에서는 전역 표준편차를 쓴다
나눗셈이 사라지므로 값이 폭발할 위험도 없어졌다

그리고 측정 결과를 모듈로 옮겼다
오디오와 화자 식별자를 넘기면 126차가 나오고, 기준점이 섰는지 여부를 함께 알려준다

실시간 여유도 확인했다
말하는 속도의 17배로 처리하므로 XR 실시간 적용에 문제가 없다
다만 발화가 끝나야 처리가 시작된다는 구조적 제약이 있다

산출물의 범위로 잡은 63차 추출과 층2 계산이 모두 코드로 존재하게 되었다
모듈 하나를 가져가면 오디오에서 126차까지 나온다

그런데 여기서 걸리는 것이 하나 있다
실전 모듈은 실험과 네 군데가 달라졌다
기준점 방식, 표준편차, 기준점 표본 수, 표준화 통계

그러면 이 모듈이 내는 벡터가 지금까지 보고한 수치와 같은 물건인가
확인하려면 채점이 필요한데 계산 자원이 없다
