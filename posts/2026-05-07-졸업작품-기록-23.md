## 사전 검증 ① VL53L5CX — 조건부 GO

### 왜 했나

VL53L5CX-SATEL이 ESP32-S3 + Arduino framework + PlatformIO 환경에서 안정적으로 동작하는지 미리 확인해야 했다. 후보 라이브러리는 SparkFun_VL53L5CX_Arduino_Library였는데, 마지막 commit이 2022년 11월이라서 ESP32-S3 호환성이 불확실했다. 5/11 ToF 단독 테스트 직전에 결판내야 코드 재작성을 피할 수 있었다.

### 진행 방식

Claude Code MCP에 위임했는데, find-skills + firecrawl + playwright + context7 조합으로 4가지 항목을 조사하도록 지시했다. 공식 문서 ESP32-S3 지원 명시 여부, GitHub 사용 사례 수, 알려진 버그, 대안 라이브러리 상태가 조사 항목이었다.

### 결과

공식 문서에는 ESP32-S3 지원이 명시되어 있지 않았다. `Compatibility = "all architectures"` generic 표현만 있었는데, 이게 실제 동작을 보장하지는 않았다.

GitHub 사용 사례는 정확 2건이 확인됐다.

- **[susesKaninchen/OnlyFeet](https://github.com/susesKaninchen/OnlyFeet)** — XIAO ESP32-S3 Sense + 8x8/15Hz + FreeRTOS 통합. 2026-05 기준 활성 상태.
- BackLogers/Mini-AI-Camera-Module

open issue는 0건이었고, closed issue 1건은 다중 센서 한정 이슈라서 단일 센서 구성인 우리 경우와 무관했다.

결론: **조건부 GO**.

### 4가지 워크어라운드

| # | 내용 |
| --- | --- |
| 1 | I2C 클럭 1MHz 설정 (`Wire.setClock(1000000)`) — PR #9 권장 |
| 2 | SparkFun 정품 / SATEL 모듈 한정 사용 (제네릭 모듈은 init fail 사례 있음) |
| 3 | 단일 센서 구성 유지 (issue #5 회피) |
| 4 | 폴백 라이브러리 사전 결정: `adafruit/Adafruit_VL53L5` lib_deps에 미리 명시 |

### 핵심 발견: OnlyFeet repo

OnlyFeet이 이번 조사의 예상 외 수확이었는데, XIAO ESP32-S3 Sense + ToF 8x8/15Hz + FreeRTOS를 통합한 코드가 실제로 작동 중이었다. 본 프로젝트와 80% 매칭이었는데, 마이크 부분이 PDM vs INMP441 차이라는 점만 달랐다. 이 repo가 사전 검증 ②에서도 핵심 참조 사례가 됐다.

## 사전 검증 ② OV3660 멀티코어 — OV2640 포팅 추정 GO

### 왜 했나

XIAO ESP32-S3 Sense Pre-Soldered에 탑재된 카메라가 OV3660이었다. 신형 모델인데, 기존에 검토했던 멀티코어 패턴(카메라 메인 코어 + 마이크 다른 코어) 사례 대부분이 OV2640 기준이었다. OV3660에서 동일 패턴이 작동하는지 확인이 필요했다.

### 진행 방식

firecrawl + playwright 조합으로 GitHub 사례, Medium 글, Issue 추적을 진행했는데, 핵심 검증 질문 4개(Q1~Q4)를 기준으로 OnlyFeet repo를 우선 분석하고 유사 패턴 5건을 추가 검색했다.

### 결과

| 카테고리 | 사례 수 |
| --- | --- |
| OV3660 직접 멀티코어 사례 | 1건 (OnlyFeet, 80% 매칭) |
| 모델 명시 없음 (실질 OV3660 추정) | 4건 |
| OV3660 단독 캡처 | 2건 (Manjot Khangura Medium 등) |

Lokch777 사용자명 직접 검색은 0건이었는데, 비공개이거나 다른 플랫폼에 있는 것 같았다.

결론: **OV2640 포팅 추정 GO** (리스크 명시).

### 5/9 카메라 코드 사전 반영 7가지

| # | 설정 | 근거 |
| --- | --- | --- |
| 1 | `xclk_freq_hz = 20000000` | Medium 권장 (OnlyFeet 24MHz지만 안전한 20MHz 우선) |
| 2 | `fb_count = 2` | dual buffer 필수 |
| 3 | `fb_location = CAMERA_FB_IN_PSRAM` | PSRAM 활용 |
| 4 | `grab_mode = CAMERA_GRAB_LATEST` | 최신 프레임 우선 |
| 5 | `jpeg_quality = 12` | 화질-용량 균형 |
| 6 | `pixel_format = PIXFORMAT_JPEG`, `frame_size = FRAMESIZE_QVGA` | 표준 설정 |
| 7 | `esp_camera_fb_return()` 후 `vTaskDelay(pdMS_TO_TICKS(30))` | JPEG timeout 회피 |

### 5/21 PoC 통합 코어 분배 잠정 안

- Core 0: micTask(p4) + tofTask(p3)
- Core 1: cameraTask(p4) + wifiTask(p3)

이건 잠정 안이라서 5/12 self-checkpoint에서 단독 테스트 4개 결과를 보고 최종 확정할 예정이다.

알려진 충돌 2건도 워크어라운드를 미리 정리해뒀다. PSRAM cache 이슈는 `-mfix-esp32-psram-cache-issue` 빌드 플래그로 대응하고, [esp32-camera issue #620](https://github.com/espressif/esp32-camera/issues/620)(WiFi join 후 fb_get fail)은 11주차 별도 검증 항목으로 등록했다.

## monorepo + PlatformIO 셋업

### 구조 결정

```
ddingdong/
├── firmware/      ← 현재 작업
├── server/        ← 11주차 진입 시
├── dashboard/     ← 15주차 진입 시
├── ml/            ← 8주차 진입 시
├── docs/
│   ├── decisions.md          ← SSoT
│   ├── decisions-log.md
│   └── git-convention.md     ← 한국어 + 이모지 14종
└── README.md
```

지금 당장 쓰는 건 firmware 폴더뿐이었는데, 나중에 합류할 트랙 위치를 미리 잡아두는 게 나중에 구조 바꾸는 것보다 낫다고 판단했다.

### platformio.ini

사전 검증 ①② 결과를 그대로 반영했다.

```ini
[env:poc]
platform = espressif32
board = seeed_xiao_esp32s3
framework = arduino
monitor_speed = 115200
upload_speed = 921600

build_flags =
  -DCAMERA_MODEL_XIAO_ESP32S3
  -DBOARD_HAS_PSRAM
  -mfix-esp32-psram-cache-issue

lib_deps =
  sparkfun/SparkFun VL53L5CX Arduino Library
  https://github.com/adafruit/Adafruit_VL53L5.git
```

`adafruit/Adafruit_VL53L5`가 PlatformIO Registry에 등록되어 있지 않아서 GitHub URL 직접 명시로 전환하는 과정에서 컴파일이 한 번 실패했는데, 워크어라운드 적용 후 통과됐다. commit 메시지는 `🔧 Settings: lib_deps Adafruit_VL53L5를 GitHub URL로 변경 (컴파일 통과 확인)`.

### 컴파일 결과

```
SUCCESS
빌드 시간: 14.25초
RAM:   5.6%  ( 18,404 / 327,680 bytes)
Flash: 7.6%  (253,821 / 3,342,336 bytes)
```

SparkFun 라이브러리 버전 1.0.3이 ESP32-S3 core 3.x와 충돌 없이 컴파일됐는데, 사전 검증 ①에서 우려했던 호환성 문제가 자동으로 해소된 셈이었다.
