이전의 실험까지 진행하면서 내가 든 생각은 이렇다.
지금까지는 내가 간단한 데이터를 만들어서 모델을 돌리고 실험했는데 실제 존재하는 많은 양의 데이터를 사용해서 모델을 돌리면 어떨까?

이러한 생각을 가지고 데이터를 조사하기로 했다.
데이터 조사 단계에서는 Claude Code MCP를 사용해서 효율적으로 그리고 정확하게 진행했다.

그 결과, KoCoSa 데이터를 발견했다.

## 1. KoCoSa는 우리 가설과 매칭

| 우리 가설 데이터 (n=4) | KoCoSa |
| --- | --- |
| 의심 발화: 표면 긍정인데 실제 비꼬기 | response: 표면 긍정 가장 + label: Sarcasm |
| 우리가 정의한 expected_intent | KoCoSa의 label (Sarcasm / Non-Sarcasm) |
| 우리 evidence 비교용 | KoCoSa의 sarcasm_explanation 필드 |
| n=4 한계 | n=12,824 |

이전 실험 구조를 거의 그대로 재사용할 수 있다. `ask_gemma()` 함수도, 평가 로직도 그대로 두고 데이터 소스만 교체하면 된다.

## 2. 그런데 결정적 한계: 멀티모달 X

KoCoSa의 modalities는 텍스트뿐이다.

우리 1차년도 가설은 사실 두 갈래다.

(a) Gemma가 sarcasm을 텍스트만으로 잡는가? → KoCoSa로 검증 가능
(b) Gemma가 멀티모달 신호(심박/표정)를 제대로 통합하는가? → KoCoSa로 검증 불가

오늘 우리가 발견한 핵심은 (b) 쪽이다 (양방향 의심 편향, Motivated Reasoning).
KoCoSa는 (a)만 검증할 수 있다.

즉, KoCoSa는 우리 1차년도 가설의 절반만 검증한다.

나머지 절반인 멀티모달 통합 검증은 MUStARD(영어 멀티모달) 또는 AI Hub 신청 데이터가 필요하다.

## 3. MUStARD를 주목해야 하는 이유

| MUStARD | 의미 |
| --- | --- |
| 690 dialog 클립 | 작은 편이지만 통계 가능 |
| 영상 + 오디오 + 텍스트 | 멀티모달 신호 보유 |
| ACL 2019 | 학술적으로 검증됨 |

우리 (b) 가설 검증의 유일한 즉시 가용 데이터다.
Claude Code도 "모달리티 일반화 검증에 유일하게 적합"이라고 명시했다.

영어라는 단점은 있지만:

- 텍스트 부분만 한국어로 번역해서 입력하는 방식 가능
- 또는 영어 그대로 검증해서 모달리티 통합 한계는 모델 일반적 속성임을 입증

## 4. 그래서 내가 정한 전략: 이중 트랙 (Dual Track)

```
[즉시 트랙] KoCoSa 다운로드 → (a) 가설 검증
  - 한국어 sarcasm 1000+ 샘플
  - 우리 n=4 결과의 일반화
  - 1~2일 내 결과 가능

[병행 트랙] MUStARD 검토 → (b) 가설 검증 준비
  - 멀티모달 통합 한계 검증
  - 영어이지만 모달리티 통합 메커니즘은 모델 일반적
  - 1주일 단위 작업

[백그라운드] AI Hub 신청 → 한국어 멀티모달 확보
  - 지금 신청만 걸어두기
  - 1~3일 후 다운로드 가능
  - 다음 주 작업
```

세 트랙을 동시에 굴리는 게 시간 효율 최대다.

이번 회차에서는 즉시 트랙(KoCoSa)부터 시작한다. 그리고 KoCoSa를 받자마자 모델을 돌리지 않고, EDA(탐색적 데이터 분석)부터 진행하기로 했다. 데이터의 구조와 분포를 모르고 모델을 돌리면, 결과가 나와도 왜 그런 결과가 나왔는지 해석할 수 없기 때문이다.
