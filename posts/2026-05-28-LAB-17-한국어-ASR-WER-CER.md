## WER vs CER

오류율 = (대체 + 삽입 + 삭제) / 정답의 단위 개수
즉, 정답을 예측으로 바꾸려면 몇 번 고쳐야 하는가 를 정답 길이로 나눈 것

### 1. WER

- 단어(공백 기준 어절) 단위

정답 어절: [몬터규는, 자녀들이, 사랑을] → 3개
예측 어절: [본, 토큐는, 자녀들이, 사랑을] → 4개

### 2. CER

- 글자(음절) 단위

정답 글자: 몬 터 규 는 (공백) 자 녀...
예측 글자: 본 토 큐 는 (공백) 자 녀...

```
영어는 띄어쓰기가 단어 경계로 안정적이라 WER(단어 단위 오류율)이 표준인데,
한국어는 띄어쓰기 규칙이 유연해서 문제가 생김

모델이 "몬터규는"을 "본 토큐는"으로 띄어 쓰면, 음절은 거의 맞혔는데도 WER은 단어 경계가 다 어긋나서 점수가 폭증
그래서 글자(음절) 단위로 보는 CER이 순수 인식 성능을 더 정직하게 보여줌

실제로 한국어 ASR 논문들(예: arXiv 2410.18444)도 CER·WER을 병기하고, 한국어 띄어쓰기 변이를 보정한 sWER까지 함께 쓰는 게 관행

-> 위 방식을 따르기로 결정
```

## 실험 설계

- CER: 공백 제거 후 음절만 -> 순수 음절 인식력
- WER: 공백 유지 (표준) -> 띄어쓰기 포함한 단어 단위 성능
- sWER: 공백 정규화(중복공백→단일, 양끝 trim)한 WER -> 띄어쓰기 변동만 봐주는 중간 지표
- N = 10으로 시작 → 검증되면 키우기

---

## 실험 과정

#### 정규화 함수

```python
# 공통 전처리: 소문자화 + 구두점/기호 제거 + 양끝 공백 정리
def base_normalize(text: str) -> str:
    text = text.lower()
    text = re.sub(r"[^\w\s가-힣]", " ", text)  # 한글/영숫자/공백만 남김
    return text.strip()

# CER용: 공통 + 모든 공백 제거 (음절만)
def norm_for_cer(text: str) -> str:
    return re.sub(r"\s+", "", base_normalize(text))

# WER/sWER용: 공통 + 연속 공백 단일화 (어절 경계 유지)
def norm_for_wer(text: str) -> str:
    return re.sub(r"\s+", " ", base_normalize(text))
```

위 정규화 함수를 간단히 검증해보자

```python
ref = "몬터규는 자녀들이 사랑을"
hyp = "본 토큐는 자녀들이 사랑을"

# 정규화 결과 눈으로 확인
print("[CER 입력]")
print("  ref:", norm_for_cer(ref))
print("  hyp:", norm_for_cer(hyp))
print("[WER 입력]")
print("  ref:", norm_for_wer(ref))
print("  hyp:", norm_for_wer(hyp))
print()

# 지표 계산
cer = jiwer.cer(norm_for_cer(ref), norm_for_cer(hyp))
wer = jiwer.wer(norm_for_wer(ref), norm_for_wer(hyp))
print(f"CER = {cer:.3f}")
print(f"WER = {wer:.3f}")
```

결과를 보면 CER의 오류율은 0.273, WER의 오류율은 0.667이다.
즉, 글자 단위로 보면 오류율이 0.273이며 단어 단위로 보면 오류율이 0.667인 것이다.

CER이 낮다고 WER보다 더 정확한 측정을 하는 것은 아니다.
한국어에서 CER을 주로 보는 것은

***점수가 잘 나와서 그런 것이 아닌 띄어쓰기 변동에 덜 휘둘려서 모델의 진짜 인식력을 더 정직하게 보여주기 때문임***

자 이제 하나의 샘플만이 아니라 여러 개의 샘플을 통해 실험을 해볼 것이다.
우선 N = 10으로 설정해서 **10개의 샘플**을 가지고 모델의 예측값을 보았다.

![](https://velog.velcdn.com/images/xorms/post/1f07c050-36c6-4370-8bd7-cc3c23457f77/image.png)

- 모델은 대부분의 발화를 정확히 인식하나, 정답과 표기 방식이 달라 오류로 집계되는 사례가 다수
- 숫자 표기 불일치: 정답은 한글("삼십 퍼센트", "오 쩜 구 사"), 예측은 아라비아 숫자("30%", "5.94") - [3][5][8][9]
- 고유명사 오인식: 몬터규->본 토큐, 회스->퓌스, 에우노토사우르스->에운 오토사우루스 - [1][8][10]
- 띄어쓰기 차이: 크루즈관광객->크루즈 관광객 등 거의 전 샘플
- 환각(hallucination): [2]번에서 정답에 없는 발화를 길게 생성 (점수 급등 원인)

여기서 2번을 보면 정답에 없는 발화, 즉 오디오 샘플에 없는 발화를 예측할 때 길게 추가로 생성하는 환각 현상이 발생했다.

![](https://velog.velcdn.com/images/xorms/post/9770439b-2781-4847-9d57-01e84b9bb8e7/image.png)

즉, 위 사진을 보면 환각현상을 제외하고 측정하자 오류율이 확 줄어든 것을 알 수 있다.
-> 이것은 N(샘플 수)이 작을 때 단일 이상치가 평균 지표를 크게 왜곡함을 알 수 있는 것이다.
.
.

이번에는 N = 30으로 설정해서 30개의 샘플을 가지고 모델의 예측값을 살펴보았다.

![](https://velog.velcdn.com/images/xorms/post/0a0a05ef-9a34-4681-af5c-52d04be95028/image.png)

- Zeroth-Korean test split 30개 샘플 기준 corpus CER 0.117 / WER 0.321
- N=10일 때(CER 0.230)보다 낮아짐: 환각 샘플 1개가 10%에서 3.3% 비율로 희석된 결과
- CER 상위 5개 중 1위([2]번, CER 1.220)는 환각(없는 발화 생성), 나머지 4개(15·5·8·9번)는 모두 숫자 표기 불일치
- 숫자 표기 불일치 예: "삼십 퍼센트"->"30%", "이백 만"->"200만", "십 칠 십 팔 대"->"17, 18대"
- 즉 CER을 끌어올리는 주 원인은 모델의 인식 오류가 아니라, 정답(한글 표기)과 예측(아라비아 숫자)의 표기 차이
- 모든 샘플에서 WER > CER (corpus 기준 0.321 vs 0.117): 한국어 띄어쓰기/표기 변동이 WER을 약 2.7배 부풀림
