앞서 말한 LoRA 파인튜닝을 하기 전 목표를 정했다.

## 목표

무엇을 가르치는가 → **"회의실 음성(잡음, 겹침, 원거리 마이크)을 들어도 제대로 전사해라"**
→ KconfSpeech 전체 분포(짧은 것 + 긴 것)를 학습에 씀

**장점**
- 임팩트가 큼 → 전체 CER이 내려가면 downstream(의도 분석, 화자 분리)에 직접 기여
- 사전학습 모델 → 도메인 적응 → 멀티모달 의도 분석 흐름이 자연스러움
- 짧은 발화 이상 행동도 어느 정도 함께 개선될 가능성 존재

모델 셋업부터 해보자.

## 1. 학습 데이터 구성

### ① 샘플 수

**[ 전체 ]**
- 도메인 적응의 핵심 = 모델이 "이 환경의 다양한 소리 패턴"을 충분히 보는 것
- 2436개면 9개 세션 × 다양한 화자 × 다양한 발화 길이가 골고루 포함
- 세션별 편차가 존재하는 상황에서 특정 세션에 편향되지 않고 전반적으로 적응할 수 있음
- 시간 비용이 큼

**[ 샘플링 ex 600 ]**
- 파인튜닝 파이프라인이 정상 작동하는지 먼저 확인하는 전략
- 첫 파인튜닝 시도에서 한 번에 완벽하게 되는 경우는 드묾
- 세션 편향 가능성 존재 - 600개 랜덤 샘플이 특정 세션에 몰리면 도메인 적응이 왜곡
→ 세션별 균등 샘플링으로 해결 가능

### ② train/val split

**[ 9:1 ]**
- 검증셋이 작으면 val loss/CER 수치가 불안정함
→ 샘플 몇 개 차이로 수치가 튀어서 "언제 학습을 멈춰야 하는가" 판단이 어려워짐

**[ 8:2 ]**
- 검증셋이 충분해야 세션별 CER, 짧은 발화 환각률 등 서브셋 분석이 의미 있음
- 파인튜닝 전후 비교가 이 연구의 핵심 → 검증셋이 빈약하면 결론의 신뢰도가 낮아짐

**결정**

- 1단계: 세션 균등 샘플링 600개 + 8:2 split으로 파이프라인 검증
  → 목적: 학습 결과가 아닌 파이프라인이 끝까지 돌아가는지 검증
- 2단계: 전체 2436개 + 8:2 stratified split으로 본 학습
  → 파이프라인 검증 완료 후 전체 데이터로 확장
  → 세션별 stratify(비율 맞춰서 자르기) 필수

## 3. (1단계) LoRA 부착

```python
# LoRA 부착

    task_type=TaskType.CAUSAL_LM,

```

**audio tower 동결 이유**

Gemma-4: 멀티모달이라 내부가 크게 둘로 나뉨
- audio tower(귀): 소리를 숫자 표현으로 바꾸는 부분 (소리 → 특징)
- language model(뇌): 귀가 바꿔준 표현으로 텍스트를 생성하는 부분 (특징 → 텍스트)
- 동결(freeze): 해당 부분은 학습 중엔 절대 안 바꿈

**메모리**
- 귀까지 학습하면 1억 5천만개가 학습 대상에 추가 → 부담

**귀는 이미 충분히 좋음**
- audio tower은 이미 엄청난 양의 오디오로 사전학습돼서 소리 → 특징 추출 이미 잘함
- 우리가 가진 603개로 귀를 다시 가르치면 오히려 붕괴 위험 존재

**문제의 위치가 뇌쪽임**
- 오디오 정보가 부족하면 LLM(뇌)가 멋대로 채움: 환각 원인
- 즉, 고쳐야 할 것은 뇌가 회의 음성 특징을 어떻게 해석하냐지, 귀가 소리를 못 듣는게 아님

## (1단계) 4. 단일 샘플 검증

본 실험에서 하려고 하는 것은 모델에게 문제집을 먹이는 일이다.
그런데 모델은 글자를 먹지 못하고 숫자(토큰)만 먹을 수 있다.
그래서

- 우리가 가진 것: [오디오 파일] + "감사하빈다."(정답 글자)
- 모델이 먹는 것: [숫자, 숫자, 숫자, 숫자, ...]

위 변환 과정이 제대로 되는지 샘플 1건으로 검증을 해보려 한다.

**1단계: 오디오 + 정답을 모델 형식으로 변환**

오디오 파일 하나를 불러오고(librosa.load) 정답 텍스트랑 같이 묶어서 프로세서에 넣기
→ 이 때, 대화 형식으로 포장
```
사용자: [오디오] "이 음성을 한국어로 전사하세요"
모델: "감사합니다."
```
즉, 마치 채팅처럼 사용자가 오디오 주면서 전사해달라고 하고, 모델이 답을 하는 형태

**결과**
- 반환 성공
- input_ids: 67개 토큰(전체 대화를 숫자로 바꾼 것)
- input_features: 오디오를 숫자로 바꾼 것

**2단계: 문제 발견**

모델한테 67개 토큰을 통째로 주면서 "이거 다 배워"라고 하면 안 된다.
그 67개 안에는
```
[오디오] + "이 음성을 전사하세요" (← 이건 질문, 매번 사용자가 주는 것)
+ "감사합니다." (← 이게 진짜 정답, 모델이 배워야 할 것)
```
이렇게 질문까지 배우면 모델이 망가짐 → "이 음성을 전사하세요"를 정답인 줄 알고 따라 말하게 되기 때문
즉, 67개 중 정답인 '감사합니다' 부분만 콕 집어서 배우라고 표시해줘야 함 → 라벨링

라벨링을 해주기 위해서 67개 토큰을 펼쳐보았다.

```
...
59: 'model'      ← "여기부터 모델 답변이야" 신호
60: '\n'
61: '감'   ┐
62: '사'   │  ← 이게 정답!
63: '합니다' │
64: '.'    ┘
65: '<turn|>'    ← "답변 끝" 신호
model 다음부터 <turn|> 까지가 정답
이 규칙을 코드로 만들면 모든 샘플에 자동 적용이 가능함
신호 토큰들의 번호 확인

<|turn> = 105, model = 4368 → 이 둘이 붙어 나오면 "정답 시작"
<turn|> = 106 → "정답 끝"
```

**3단계: 정답만 추출하는 함수 생성**

```python
TURN_OPEN = 105    # <|turn>
MODEL_TOK = 4368   # model
TURN_CLOSE = 106   # <turn|>
NEWLINE = 107      # \n

def build_labels(input_ids_1d):
    """어시스턴트 응답 구간만 label로 살림. model\n 다음 ~ <turn|> 포함까지."""
    ids = input_ids_1d.tolist()
    labels = [-100] * len(ids)

    # [105, 4368] = 어시스턴트 턴 시작
    start = None
    for i in range(len(ids) - 1):
        if ids[i] == TURN_OPEN and ids[i + 1] == MODEL_TOK:
            start = i + 2  # 'model' 다음
            break
    if start is None:
        return torch.tensor(labels)

    # model 다음의 줄바꿈(\n) 건너뛰기
    while start < len(ids) and ids[start] == NEWLINE:
        start += 1

    # 정답 구간: start ~ 종료마커(<turn|>) 포함까지
    for i in range(start, len(ids)):
        labels[i] = ids[i]
        if ids[i] == TURN_CLOSE:  # <turn|> 살리고 종료
            break
    return torch.tensor(labels)

labels = build_labels(input_ids)
valid = labels[labels != -100]
print(f"정답 원본:    {repr(ref_text)}")
print(f"label 디코딩: {repr(processor.decode(valid))}")
print(f"label 토큰 수: {len(valid)}")

print(f"\n[label!=-100 상세]")
for tid in valid.tolist():
    print(f"  {tid} -> {repr(processor.decode([tid]))}")
```

**결과**
```
정답 원본:    '감사합니다.'
label 디코딩: '감사합니다.<turn|>'
label 토큰 수: 5

[label!=-100 상세]
  239012 -> '감'
  237470 -> '사'
  19773 -> '합니다'
  236761 -> '.'
  106 -> '<turn|>'
```

모델이 입력을 확인하고 "감사합니다."라는 정답 부분만 학습 대상으로 표시하는데 성공했다는 뜻
→ 모델이 문제집을 보고 정답인 부분에만 형광펜을 칠할 수 있게 된 것임 (아직 출력, 학습 아무것도 안 함)
