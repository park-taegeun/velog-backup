# 졸업작품 기록 (6)

Flask 서버 기술 스택 선정 — AWS, Nginx, Gunicorn, SQLite

ML 기술 스택을 확정하고 나서 다음 고민은 서버 쪽이었다.
Flask 앱을 어디에, 어떤 구조로 올릴 것인가를 결정해야 했고,
그 과정에서 선택한 것들을 하나씩 정리해봤다.

## 플랫폼: AWS EC2

### AWS란

아마존이 운영하는 클라우드 서비스인데, 아마존 데이터센터에 있는 자원을 인터넷으로 빌려 쓰는 것이다.

GCP(Google Cloud Platform)도 선택지였는데, AWS를 고른 이유는 네 가지였다.

- GCP Cloud Run 대비 한국어 레퍼런스가 압도적으로 많음
- Docker 없이 바로 Flask를 올릴 수 있어 진입장벽이 낮음
- Claude Code 같은 AI 툴로 작업할 때 수월
- Free Tier t2.micro 1년 무료

### EC2란

클라우드에서 가상 컴퓨터 한 대를 빌리는 서비스인데, 물리적인 서버 한 대를 소프트웨어로 여러 개로 쪼개는 가상화 기술을 기반으로 한다.
EC2에서 빌린 가상 컴퓨터 한 대를 인스턴스라고 부르는데, 인스턴스마다 CPU, RAM, 저장공간 사양이 다르다.

시작은 t2.micro(RAM 1GB) 로 하고, 필요하면 t2.small(RAM 2GB) 로 업그레이드할 예정이다.

### 리전: 서울

AWS 데이터센터는 전 세계에 있어서 어느 나라 서버를 쓸지 고르는 게 리전 선택인데, 서울 리전을 택했다. ESP32 → 서버 간 거리가 가까울수록 지연시간이 짧아지고, 5초 이내 알림 요구사항에 유리하기 때문이었다.

### 보안: Let's Encrypt + HTTPS

Let's Encrypt로 무료 SSL 인증서를 발급받아 EC2에 도메인을 연결하면 HTTPS가 완성된다.
ESP32는 setInsecure()로 인증서 검증을 생략하는데, 이 부분은 졸업작품 한계점으로 문서화해둘 예정이다.

## 실행 구조: Nginx → Gunicorn → Flask

### Nginx — 리버스 프록시

프록시에는 두 종류가 있는데,

- 포워드 프록시: 클라이언트 앞에 서서 클라이언트 대신 요청을 보내주는 것 (VPN과 유사한 개념)
- 리버스 프록시: 서버 앞에 서서 클라이언트 요청을 받아 서버한테 넘겨주는 것

Nginx는 리버스 프록시 역할을 하는데, 이 프로젝트에서 핵심은 SSL Termination이었다.

```
ESP32 (HTTPS 요청)
        ↓
      Nginx (포트 443)
        ├── HTTPS 복호화 (SSL Termination)
        ├── 요청을 내부 포트 8000으로 전달
        └── Gunicorn한테 넘김
```

HTTPS는 암호화된 통신인데, 암호화/복호화를 Nginx가 전담해주니까 Gunicorn이랑 Flask는 암호화를 신경 쓰지 않고 로직만 처리하면 된다.

- 외부(ESP32) ↔ Nginx: HTTPS (암호화)
- Nginx ↔ Gunicorn ↔ Flask: HTTP (내부 통신이라 암호화 불필요)

### Gunicorn — WSGI 서버

Nginx는 HTTP 요청을 받을 수 있는데 Flask 앱을 직접 실행하지는 못한다.
둘 사이에 번역가 역할을 하는 게 WSGI(Web Server Gateway Interface) 이고, Gunicorn이 그 WSGI 서버다.

```
Nginx(웹 서버) → Gunicorn(WSGI 서버) → Flask(WSGI 앱)
```

Flask 내장 서버는 싱글 스레드라 요청을 하나씩 처리하고, 에러가 나면 그냥 죽는 개발용 서버인데,
Gunicorn을 쓰면 세 가지가 달라진다.

- 워커 프로세스 여러 개를 띄울 수 있어서 요청을 병렬 처리
- 워커 하나가 죽으면 자동으로 새 워커 생성
- 프로덕션 환경에서 검증된 안정성

워커는 2개로 설정할 예정이다.

## 로그 저장: SQLite

Flask 서버가 동작하면서 아래와 같은 기록을 남겨야 한다.

```
2026-04-06 18:32:11 | 초인종 | 신뢰도 92% | 알림 전송 ✅
2026-04-06 18:45:03 | 불명확 | 신뢰도 45% | 알림 미전송 ❌
2026-04-06 19:01:55 | 화재경보 | 신뢰도 97% | 알림 전송 ✅
```

SQLite로 확정했다. 이유는 세 가지였는데, 웹 대시보드에서 날짜별/종류별 필터링이 필요했고, 별도 DB 서버 없이 파일 하나(logs.db)로 동작하는 구조라 EC2에 추가 설치가 필요 없었고, Flask-SQLAlchemy 라이브러리 하나로 연동이 끝났다.

SQLAlchemy는 ORM(Object Relational Mapper) 인데, SQL을 직접 안 써도 파이썬 코드로 DB를 조작할 수 있게 해준다.

```python
# SQL로 쓰면
SELECT * FROM logs WHERE sound_type = '초인종'

# SQLAlchemy ORM으로 쓰면
Log.query.filter_by(sound_type='초인종').all()
```

## 전체 흐름 정리

```
ESP32 (HTTPS POST)
        ↓ 포트 443
      Nginx
        - SSL Termination (HTTPS → HTTP)
        - Let's Encrypt 인증서 적용
        - 요청을 localhost:8000으로 전달
        ↓ 포트 8000
      Gunicorn
        - 워커 프로세스 2개
        - Flask 앱 안정적 실행
        - 워커 죽으면 자동 재시작
        ↓
      Flask 앱
        - WAV 수신
        - librosa → 멜 스펙트로그램 변환
        - YAMNet 추론
        - 코사인 유사도 2차 필터 (초인종 한정)
        - 카카오톡 전송
        - 로그 기록 (SQLite)
        ↓              ↓
   카카오톡 알림    React 웹 대시보드
```
