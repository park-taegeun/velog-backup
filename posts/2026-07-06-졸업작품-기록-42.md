## 데이터 채우는 하루인 줄 알았는데 — AI가 잡은 방향을 세 번 되돌린 이야기

### 모델은 됐는데, 그게 어떻게 보이는지는 못 봤다

데이터 파이프라인을 세우고, 예비학습으로 test 88.7%를 찍고, 그 모델을 서빙용 SavedModel로 뽑는 것까지 며칠 사이에 끝냈다. 근데 정작 그 결과가 사용자 화면에 어떻게 뜨는지는 한 번도 못 봤다.

실제 알림 데이터는 하드웨어(현관 장치)가 붙어서 소리를 잡고 서버로 쏴야 들어오는데, 그건 한참 뒤 일이다. 그래서 "그 전에 대시보드 UI만이라도 미리 눈으로 보자"로 이번 작업을 시작했다. 목표만 놓고 보면 되게 단순했는데 — 이 단순한 걸 AI에게 맡기니까, 자꾸 엉뚱한 방향으로 샜다.

지난 두 글이 "AI가 만든 산출물의 진위를 어떻게 걸렀나"였다면(파이프라인의 데이터 함정, export의 검증 3층위), 이번 글은 결이 다르다. 결과물이 맞는지가 아니라, 애초에 어디로 갈지를 세 번 바로잡은 이야기다. 감독해야 할 지점이 결과에서 과정으로, 다시 목적으로 점점 앞단으로 올라간 셈이다.

### 방향 하나 — 목적을 잘못 잡다

일을 벌이자마자 첫 단추가 어긋났다. 의사결정을 맡긴 LLM이 이걸 "발표 데모 자산 만들기"로 프레임하고, 시연 시나리오를 짜고 이미지 저작권까지 따지기 시작했다. 얼핏 그럴듯한데, 내가 하려던 건 그게 아니었다.

그래서 "발표용 자산이 아니라, 실 데이터 들어오기 전에 UI가 실제로 어떻게 보일지 미리 확인하는 것"이라고 목적을 다시 잡아줬다. 사소해 보여도 이게 이후 모든 기술 판단의 분기점이었다. 목적이 "발표 자산"이면 화면을 그럴듯한 숫자로 채우는 게 맞지만, "미리보기"라면 실제로 어떻게 보일지가 기준이 된다. 뒤에 나올 타이밍 카드 문제에서 이 한 줄 차이가 정반대의 결론을 냈다.

### 방향 둘 — 위임 전제가 실측 앞에서 무너지다

목적을 잡고, "대시보드 화면을 채우려면 서버 mock 데이터를 채우면 되겠지"라는 전제로 조사 위임을 던졌다. 근데 코딩 에이전트(Claude Code)가 repo를 실제로 까보니, 그 전제가 네 군데서 다 틀렸다.

| 전제 | 실측 결과 |
| --- | --- |
| dashboard mock-data.ts 채우면 화면 반영 | 아무 데서도 import 안 하는 죽은 참조 |
| 서버 mock을 쓰면 됨 | 결정론이 안 되는 랜덤 생성기 (매번 다른 값) |
| 기존 DB 레코드로 보면 됨 | 날짜가 3주 전이라 "오늘" 필터에 안 걸림 |
| 사진도 같이 뜸 | 정적 서빙 경로가 없어 항상 fallback 이미지 |

여기서 맹목적으로 밀지 않고 막힘 트리거로 일단 멈추고 판단을 물어온 게 좋았다. 진짜 방법은 server/seed.py를 새로 만들어서, 실제 DB에 결정론적으로 5건을 심는 거였다(초인종 완료 / 노크 완료 / 노크 2차 처리중 / 화재 우회 / 초인종 미발송). detected_at을 now - timedelta(...)로 잡아서 항상 "오늘"에 걸리게 했고, delete() 후 add_all로 몇 번을 다시 돌려도 같은 상태가 되게 했다.

파이프라인·export에 이어 여기서도 "AI 진단을 코드로 재검증한다"는 원칙이 또 걸렸는데, 이번엔 성격이 좀 달랐다. 앞선 둘은 코드의 원인 진단이 틀린 거였다면, 이번엔 작업 방법의 전제 자체가 틀렸다. "어디를 고치면 되는가"가 아니라 "어떻게 하면 화면이 채워지는가"가 실측 앞에서 무너진 거다.

### 방향 셋 — '가짜로 채우기'의 유혹을 접다

seed로 데이터를 넣고 나니 다른 카드는 다 살았는데, 알림 속도 타이밍 카드만 0ms / 0%로 죽어 보였다. 처음엔 "이것도 seed로 그럴듯하게 채우자" 싶었다. 근데 실측하니 stats가 timing을 아예 하드코딩 0으로 반환하고 있었다(주석에 "실 계측 도입 전 placeholder"라고 적혀 있었음). seed로 타임스탬프를 넣어도 그 값이 계산에 안 쓰여서 seed만으론 못 채우는 구조였다.

여기가 갈림길이었다. 서버 코드를 데모용으로 만져서 억지로 숫자를 띄우느냐. 결론은 "데모 픽션을 주입하는 게 아니라, 미구현이던 실 계측을 앞당기는 것"으로 났다. 지연을 계산하는 데 필요한 데이터(detected_at, primary_sent_at, secondary_sent_at)는 이미 DB에 다 들어 있었으니까, _build_stats를 고쳐서 실제 타임스탬프 델타로 집계하게 바꾸면 됐다.

```
1차 지연 = primary_sent_at - detected_at   (목표 5초 이내 달성률)
2차 지연 = secondary_sent_at - detected_at (목표 15초 이내 달성률)
필터: sent_at is not None  (미발송·2차 처리중 건은 제외)
가드: 분모 0일 때 ZeroDivision 방어
```

이렇게 하면 11주차에 실제 하드웨어 데이터가 들어와도 이 코드가 그대로 실값을 뽑는다. 버릴 데모 코드가 아니라 남는 코드가 된 거다. 원래 11주차 서버 몫이던 걸 미리 당겨온 셈이라, 결과적으로 일정상 이득이기도 했다.

목적을 "미리보기"로 잡았던 게 여기서 값을 했다. "발표 자산"이 목적이었으면 가짜 숫자로 채우는 게 정답이었을 텐데, "실제로 어떻게 보일지"가 기준이니까 가짜를 넣는 순간 목적을 배신하는 거였다.

### 방향 넷 — 사용자를 다시 떠올리다

알림 사진을 크게 볼 수 있게 전체화면 라이트박스를 붙였다. radix Dialog(shadcn)를 재사용해서, 트리거를 native `<button>`으로 두면 Enter/Space/포커스/aria가 공짜로 딸려오고, 닫기는 X 버튼(44px)·배경 클릭·ESC 세 경로를 다 열고, 포커스 트랩·복원에 스크롤 락까지 붙였다. 사진은 object-contain으로 크롭 없이 원본 비율을 지켰다.

기능은 멀쩡했는데, 여기서 사용자를 다시 짚었다. "어르신들이라 사진을 클릭하면 커진다는 걸 모를 것 같다, 우측 상단에 표시라도 있으면 좋겠다"는 거였다. 이게 어포던스 — 누를 수 있어 보이게 만드는 문제다. 타겟이 5060 노안 사용자라 hover하면 커서가 바뀌는 정도로는 발견이 안 된다.

그래서 "크게 보기" 텍스트를 Maximize2 아이콘과 병기한 뱃지를 사진 위에 항상 띄웠다. 색이나 아이콘 하나에만 의존하지 않게(WCAG 1.4.1) 텍스트를 같이 넣었고, bg-black/60에 흰 텍스트로 대비를 확보했다. 뱃지는 pointer-events-none을 줘서 클릭 히트 영역은 사진 전체로 유지되게 했고, 스크린리더에는 중복으로 안 읽히게 aria-hidden 처리했다. 기능이 있는 것과 그 기능을 발견할 수 있는 것은 다르다는 걸 다시 확인한 대목이었다.

### 곁다리 — localhost가 Flask가 아니라 AirTunes였다

마지막에 황당한 함정이 하나 있었다. 세팅이 다 끝났는데 대시보드가 데이터를 못 불러왔다. 토큰도 seed도 코드도 다 멀쩡했다.

범인은 macOS의 AirPlay 수신기였다. 이게 5000번 포트를 점유하고 있어서, Flask 대신 AirTunes가 요청을 가로채 403을 뱉고 있었던 거다. 재밌는 건 127.0.0.1:5000으로 직접 치면 Flask로 가는데, localhost:5000으로 proxy를 경유하면 AirTunes로 갈렸다는 점이다. 실마리는 응답 헤더의 Server: AirTunes였다 — 이걸 보고 나서야 코드가 아니라 OS 설정 문제란 걸 알았다.

### 마무리 — 감독의 지점이 앞단으로 올라갔다

겉보기엔 그냥 대시보드에 데모 데이터 채워서 화면 한번 본 하루였다. 근데 실제로는 목적·전제·판단 세 지점에서 AI가 잡은 방향을 사람이 되돌린 하루였다.

- 목적: "발표 데모 자산" → "실 데이터 전 UI 미리보기"
- 전제: "mock 채우면 반영됨" → 실측 4건 반박 → 실 DB 결정론 시드
- 판단: "0ms를 가짜로 채우자" → "미구현 실 계측을 앞당기자"

지난 export 글의 "검증 3층위"가 결과물이 맞는지를 걸렀다면, 이번엔 애초에 어디로 갈지를 세 번 바로잡았다. 재밌는 건 세 글을 잇고 보면, 사람이 AI를 감독하는 지점이 결과 → 과정 → 목적으로 점점 앞단으로 옮겨가고 있다는 거다. 기술 난이도는 오히려 낮아졌는데, 감독의 층위는 더 근본적인 쪽으로 올라갔다.

부수적으로 타이밍 실계측이 11주차 서버 몫에서 선작업으로 승격됐고, 노안 사용자용 사진 확대 어포던스를 챙겼고, 무엇보다 이 모델과 알림이 실제로 어떻게 보일지를 눈으로 확인했다. 다음은 이월된 코드 정합(신뢰도 임계값 코드값을 SSoT에 맞추는 것, 화재 뱃지 대비 보정)과 남은 ML 미결 2건(pitch shift 대상, SpecAugment 적용) 차례다.
