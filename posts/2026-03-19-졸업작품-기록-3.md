# 멜 스펙트로그램과 CNN 개념 정리

> 본격적으로 ML 모델을 고르기 전에 기초 개념부터 잡고 가기로 했다.
> "왜 소리를 이미지로 바꾸는가", "그 이미지를 CNN이 어떻게 처리하는가"
> 이 두 가지를 모르면 모델 선정 근거도 설명할 수 없어서 먼저 정리해봤다.

---

## 소리를 그냥 ML에 넣으면 안 되는 이유

마이크로 소리를 녹음하면 **파형(Waveform)** 데이터가 생긴다.

시간 축에 따라 진폭이 오르내리는 형태인데,

```
진폭 ↑
      | ∿∿∿∿∿∿∿∿∿∿
      └──────────────→ 시간
```

이 파형 자체를 ML에 넣을 수는 없었다.

파형은 **"진폭이 얼마냐"** 만 보여줄 뿐, **"어떤 주파수가 얼마나 들어있냐"** 는 전혀 안 보이기 때문이다.

초인종과 노크를 구별하려면 주파수 정보가 있어야 했고, 그걸 얻기 위한 과정이 멜 스펙트로그램 변환이었다.

---

## 1단계: 스펙트로그램 — 소리에서 주파수를 뽑기

### 푸리에 변환 (FT)

주파수를 뽑아내는 수학적 방법이 **푸리에 변환(Fourier Transform)** 이다.

핵심 아이디어는 단순한데,

> 어떠한 복잡한 파형도 여러 개의 단순한 사인파의 합으로 표현할 수 있다.

```
복잡한 파형 = 사인파A  +  사인파B  +  사인파C
(실제 소리)   (100Hz)     (440Hz)     (1000Hz)
```

푸리에 변환을 하면 각 주파수가 얼마나 강하게 들어있는지가 한눈에 보였다.

```
에너지 ↑
       |  █
       |  █       █
       |  █   █   █
       └──────────────→ 주파수(Hz)
         100  440  1000
```

### STFT: 시간 정보까지 살리기

일반 FT는 전체 신호를 한 번에 분석하는데, 그러면 **시간 정보가 사라진다.**

"0.5초 시점에 노크 소리가 있었다"는 걸 알 수 없는 셈이라서, 이 문제를 해결한 게 **STFT(Short-Time Fourier Transform, 단시간 푸리에 변환)** 였다.

> 전체 신호를 짧은 구간(window)으로 쪼개서, 각 구간마다 따로 푸리에 변환을 적용한다.

```
전체 신호: ────────────────────────────────
                         ↓ 쪼갬 (예: 25ms 단위)
구간1: ────   구간2: ────   구간3: ────  ...
  ↓ FT          ↓ FT          ↓ FT
스펙트럼1       스펙트럼2       스펙트럼3
```

이 결과물을 시간 순서대로 옆으로 쌓으면 2D 행렬이 됐고, 이게 **스펙트로그램**이다.

```
주파수 ↑
고  |  ░░░▒▒▓▓░
중  |  ▒▒▓▓▓▒░░     가로: 시간 / 세로: 주파수 / 밝기: 에너지 세기
저  |  ▓▓▒▒░░░░
    └──────────→ 시간
      1  2  3  4  5
```

## 2단계: 멜 스케일 — 사람 귀 기준으로 다시 표현하기

스펙트로그램의 세로축은 기본적으로 선형 구조라서,

```
주파수 ↑
8000 |
7000 |    ← 1000Hz 간격으로 동일하게 나뉨
6000 |
...
1000 |
   0 |
```

물리적 간격은 같은데 **사람이 느끼는 차이는 전혀 달랐다.**

- 저주파 영역: 작은 차이도 민감하게 구별
- 고주파 영역: 큰 차이도 잘 구별 못 함

선형 스케일 그대로 쓰면 사람이 별로 중요하지 않게 느끼는 고주파 영역이 행렬의 절반 이상을 차지하게 됐고, ML 모델 입장에서는 비효율적이었다.

**멜 스케일**은 이 문제를 해결하는 방식이었는데,

| 기준 | 선형 방식 | 멜 스케일 |
| --- | --- | --- |
| 눈금 기준 | 물리적 주파수 간격 | 사람이 느끼는 차이 |
| 저주파 표현 | 적은 행 | 많은 행 (세밀하게) |
| 고주파 표현 | 많은 행 | 적은 행 (뭉뚱그려) |

전체 행 수는 같지만 저주파에 행을 더 많이, 고주파에 덜 배정해서 **사람 귀의 특성을 반영한 표현**이 됐다.

---

## 3단계: 로그 스케일 — 값 범위 압축

멜 스펙트로그램의 각 칸 값은 소리 에너지인데, 에너지 값은 범위가 매우 넓었다.

값 차이가 너무 크면 모델이 **큰 값에만 집중하고 작은 값의 패턴을 무시**하게 되는데, 이걸 막으려고 로그를 씌워서 범위를 줄였다.

---

## 전체 흐름 정리

```
WAV 파일 (파형)
        ↓ STFT
스펙트로그램 (시간 × Hz, 선형)
        ↓ 멜 필터뱅크
멜 스펙트로그램 (시간 × Mel)
        ↓ 로그 스케일
로그 멜 스펙트로그램 (값 범위 압축)
        ↓
CNN 입력 준비 완료
```

---

## CNN — 이미지에서 특징을 뽑는 신경망

멜 스펙트로그램은 결국 2D 이미지였고, 이미지에서 특징을 자동으로 뽑아내는 신경망이 **CNN(Convolutional Neural Network)** 이다.

### 우리 소리 분류에서 "특징"이란

- 초인종: 특정 주파수 대역에서 짧고 반복되는 패턴
- 노크: 저주파에서 순간적으로 터지는 패턴
- 화재경보: 고주파에서 지속적으로 올라갔다 내려가는 패턴

사람이 이 특징을 직접 정의해서 넣는 게 아니라, CNN이 **학습을 통해 스스로 찾아낸다.**

### 어떻게 특징을 뽑나: 필터(커널)

CNN의 핵심은 **필터**였다. 필터를 이미지 위에 올려놓고 같은 위치 값끼리 곱해서 다 더하면 그 값 하나가 결과 행렬의 한 칸이 됐고, 필터가 이미지 전체를 훑고 나면 **Feature Map(특징맵)** 이 완성됐다.

어떤 필터를 쓰느냐에 따라 뽑히는 특징이 달라지는데, 그 필터 값은 **학습을 통해 자동으로 정해진다.**

처음에는 랜덤으로 시작해서 학습 데이터를 반복해서 보면서 점점 유용한 값으로 수렴해갔다.

소리를 구별하려면 여러 특징이 필요하니까 **필터를 여러 개** 썼고, 하나의 Conv 레이어는 그 필터들과 각각의 Feature Map 묶음으로 이뤄진다.

### 레이어를 쌓으면

Conv 레이어 뒤에는 **Pooling 레이어**가 따라오면서 Feature Map을 압축하는데, 이 과정을 반복하면

```
입력 (128×128)
      ↓ Conv + Pooling
      ↓ Conv + Pooling
      ↓ Conv + Pooling
출력 (8×8×64)  ← 작아졌지만 고수준 특징이 압축된 상태
```

점점 작아지면서 핵심 특징만 남게 됐다.

### 최종 분류: Fully Connected 레이어

Conv + Pooling을 반복한 결과물은 아직 3D 덩어리인데, 이걸 확률로 바꿔주는 게 **Fully Connected 레이어**였다.

```
3D 덩어리
   ↓ Flatten (3D → 1D로 펼치기)
1D 벡터
   ↓ Fully Connected (학습을 통해 조합)
   ↓ Softmax (확률 변환)
[초인종: 0.85, 노크: 0.10, 화재경보: 0.05]
```

## 정리

> **멜 스펙트로그램이 소리를 2D 이미지로 바꿔줬고,
> CNN이 그 이미지에서 특징을 자동으로 뽑아서 분류했다.**

이 흐름을 이해하고 나니 자연스럽게 다음 질문이 나왔는데,
