"무엇을 만들었다"보다 **왜 이렇게 설계했고, 무엇이 깨졌고, 어떻게 고쳤는지**에 집중해 정리합니다.

## LLM Wiki란 무엇인가

LLM Wiki는 LLM을 "사서"로 두는 개인 위키입니다. 사람은 원본(블로그 글, 메모, 대화 기록)을 넣고 질문만 합니다. 원본이 들어올 때마다 LLM이 관련 페이지를 만들거나 보강하고, 페이지끼리 링크로 연결합니다.

| 층 | 이름 | 누가 쓰나 | 이 프로젝트에서 |
| --- | --- | --- | --- |
| 1층 | raw (원본) | 사람·수집기. 추가만, 수정 금지 | `_private/raw/` |
| 2층 | wiki (정리본) | LLM | `wiki/`(공개), `_private/wiki/`(비공개) |
| 3층 | schema (규칙서) | 사람 | `CLAUDE.md` |

동작은 **Ingest**(원본을 읽고 페이지 생성·보강), **Query**(위키를 인용하며 답변), **Lint**(끊긴 링크, 고아 페이지, 모순, 중복 점검) 세 가지입니다. 고아 페이지는 어떤 페이지에서도 링크되지 않은 페이지를 말합니다.

핵심은 **복리(compounding)**입니다. 연구 기록 88편 중 MFCC(음성의 음색 특징을 숫자로 뽑는 방법)를 다룬 글은 14·45·48·52편에 흩어져 있었지만, 위키에서는 `mfcc` 페이지 하나에 누적됩니다. 원본이 들어올수록 페이지가 두꺼워지고 링크가 늘어, 위키는 쓸수록 똑똑해집니다.

### RAG와 무엇이 다른가

RAG(Retrieval-Augmented Generation)는 질문할 때마다 외부 문서에서 관련 조각을 검색해 답변에 붙이는 방식입니다.

| 항목 | RAG | LLM Wiki |
| --- | --- | --- |
| 정리 시점 | 질문할 때마다 원본 조각을 검색 | 원본을 넣을 때 한 번 정리(컴파일) |
| 결과물 | 매번 사라지는 답변 | 남아서 쌓이는 마크다운 페이지 |
| 모순 처리 | 검색된 조각끼리 충돌해도 모름 | 넣을 때 기존 페이지와 대조해 표시 |
| 사람이 보기 | 벡터DB라 들여다보기 어려움 | Obsidian 그래프·웹사이트로 바로 탐색 |

수만 건이 계속 바뀌는 사내 검색이라면 RAG가, 한 사람이나 작은 팀이 오래 쌓고 직접 읽기도 하는 기록이라면 LLM Wiki가 맞습니다.

## 설계 — 한 볼트, 두 레포

Obsidian은 사람이 보는 화면, Claude Code는 볼트 폴더(`~/Documents/AI-Vault`)에서 실행되는 사서 에이전트, CLAUDE.md는 사서의 근무 규칙입니다.

```null
AI-Vault/                          ← 공개 레포 ai-vault-wiki
├── CLAUDE.md                        규칙서 (3층)
├── wiki/{concepts,tools,projects}/  공개 위키 → 웹사이트
├── eval/                            골든 질문·평가 결과
├── .tools/                          점검 스크립트, Velog 수집기 (숨김 폴더)
├── .claude/{settings.json, hooks/guard.py, commands/, skills/velog-wiki/}
├── .githooks/pre-commit, .github/workflows/publish.yml
└── _private/                      ← 비공개 레포 ai-vault-private
    ├── raw/{notion,velog,clips,notes,chats,career,_legacy}/
    ├── wiki/{career,projects}/
    └── log.md
```

공개 위키와 비공개 원본이 한 레포에 있으면 `.gitignore` 한 줄 실수로 원본이 공개될 수 있습니다. 그래서 루트 레포는 `_private/`를 통째로 무시하고, `_private/`는 그 자체로 별도 git 레포로 만들었습니다. git은 중첩된 레포 안의 파일을 바깥 레포에 `git add -f`(무시 규칙을 건너뛰는 강제 추가)로도 넣지 못합니다. 규칙을 지켜서 안 섞이는 것이 아니라 **구조적으로 섞일 수 없게** 만든 것입니다. 분류 기준은 **애매하면 비공개, 공개 전환은 사람이**입니다.

## 4가지 설계 원칙

AX(AI 전환)·AI 엔지니어링·시스템 설계 관점에서 처음 설계를 다듬으며 세운, 이번 편의 핵심입니다.

### ① 규칙(soft)과 강제(hard)를 분리한다 — 팻말 vs 자물쇠

CLAUDE.md는 모델에게 하는 "부탁"이라 어겨질 수 있습니다. "들어가지 마시오" **팻말**입니다. 어기면 사고가 나는 규칙은 **자물쇠**, 즉 시스템이 막아야 합니다.

| 시점 | 장치 | 막는 것 |
| --- | --- | --- |
| 파일을 쓰는 순간 | `guard.py` (PreToolUse 훅) | 원본 수정, 공개 구역에 비밀값·개인정보 쓰기, Bash로 원본 삭제·덮어쓰기 |
| 권한 | `settings.json` deny | push, `--no-verify`, `git config`, `.obsidian/`·`.env` 읽기, 가드·스크립트 자기 수정 |
| 공개 레포 커밋 | `.githooks/pre-commit` | 비공개 경로, 비밀값·개인정보, 공개→비공개 링크 |
| 비공개 레포 커밋 | `_private/.githooks/pre-commit` | 살아 있는 API 키·토큰 |
| 배포 | GitHub Actions public-gate | 공개 파일 전수 재검사, 실패 시 배포 중단 |

**PreToolUse 훅**은 도구 실행 직전의 검문 스크립트(exit 2면 차단), **deny 권한**은 Claude Code가 아예 거부하는 동작 목록, **pre-commit 훅**은 커밋 직전에 git이 돌리는 검사입니다. 그리고 **push는 항상 사람이 합니다.** AI는 커밋까지만 합니다.

실제로 시험해 본 결과입니다.

| 시도 | 결과 |
| --- | --- |
| `.obsidian/` 파일 읽기 (Read 도구) | `File is in a directory that is denied by your permission settings` |
| Bash로 우회 (`cat .obsidian/app.json`) | 역시 거부 |
| 원본 파일 Write | `[가드] ... — CLAUDE.md 9장. 우회하지 말고 사람에게 보고하세요.` |

가드 메시지에 "규칙서 몇 장 위반인지"와 "우회하지 말고 보고하라"를 넣으면, Claude는 다른 길을 찾는 대신 멈추고 보고합니다.

### ② 답이 정해진 일은 코드가, 판단이 필요한 일은 LLM이

**결정론적(deterministic)** 작업은 같은 입력이면 항상 같은 결과가 나오는 작업입니다. LLM에게 "링크 몇 개야?"를 세게 하면 틀리기도 하고 토큰도 낭비됩니다.

| 담당 | 작업 |
| --- | --- |
| `wiki_check.py` (코드) | 링크 개수, 끊긴 링크, 고아 페이지, 마감일 계산, 미처리 원본 찾기 |
| Claude (LLM) | 모순 판단, 중복 판단, 공개/비공개 분류 |

`/lint`도 스크립트가 기계적인 문제를 먼저 뽑고 Claude가 의미 판단을 덧붙이며, 사람이 승인한 번호만 수정합니다.

### ③ 병렬로 쓰되, 공유 상태는 한 명만 고친다

88편을 빠르게 처리하려고 **서브에이전트**(메인 에이전트가 띄우는, 별도 컨텍스트를 가진 분신)를 병렬로 띄웠습니다. 그런데 여럿이 동시에 같은 페이지를 고치면 서로의 수정을 덮어씁니다. 그래서 **single writer(단일 작성자)** 원칙을 적용했습니다. 서브에이전트는 `_private/drafts/`에 초안만 쓰고, 병합·목차·로그는 메인 에이전트 혼자 고칩니다.

같은 개념이 `mfcc`와 `MFCC-특징`처럼 두 이름으로 갈라지는 문제도 있습니다. 그래서 병렬 시작 전에 **용어집(glossary)**을 먼저 승인받아 페이지 이름을 고정했습니다.

![](https://velog.velcdn.com/images/xorms/post/43641f08-69b0-4b8c-8a97-895849bcc740/image.png)

![](https://velog.velcdn.com/images/xorms/post/3d9349b3-82ee-416d-9a6e-3295cd8fc0e9/image.png)

용어집에는 페이지 이름, 한 줄 설명, 들어갈 원본 번호, 묶음 공통 공개 기준이 담겼습니다. 결과적으로 연구 기록 병렬 초안끼리 **페이지 이름 불일치 0건**, 졸업작품 반영 때 용어집 밖에서 새로 생긴 이름 10개도 모두 승인된 이름 규칙을 따랐습니다.

### ④ "복리로 똑똑해진다"를 측정한다

- **골든 질문 eval**: 고정된 질문을 질문마다 **새 서브에이전트**에게 답하게 합니다. 이전 맥락 없이 위키만 보고 답하게 해서 검색 적중, 사실 정확, 위키만으로 답했는지를 채점하고 추이를 기록합니다.
- **자동화 준비도**: 최근 14일 `/velog-wiki` 실행 5회 이상, 사람이 Claude의 판단을 고친 횟수(correction) 1회 이하일 때만 다음 자동화 단계를 검토합니다.

## 구현

### 키트 설치와 권한 설정

```bash
bash setup.sh ~/Documents/AI-Vault
git config core.hooksPath .githooks          # 클론해도 훅 설정은 따라오지 않음
git -C _private config core.hooksPath .githooks
```

`setup.sh`는 볼트를 백업하고 기존 PARA 폴더를 `_private/raw/_legacy/`로 옮긴 뒤(삭제 없음) 두 레포를 초기화합니다. 루트에 비공개 자료가 남아 있으면 **중단**합니다.

```json
{
  "permissions": {
    "deny": [
      "Bash(git push:*)", "Bash(git commit --no-verify:*)", "Bash(git config:*)",
      "Read(./.obsidian/**)", "Read(./**/.env)",
      "Edit(./.claude/**)", "Edit(./.githooks/**)", "Edit(./.github/**)", "Edit(./.tools/**)"
    ]
  },
  "hooks": {
    "PreToolUse": [{
      "matcher": "Write|Edit|MultiEdit|NotebookEdit|Bash",
      "hooks": [{ "type": "command",
        "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/guard.py\"" }]
    }]
  }
}
```

가드·훅·스크립트 폴더의 Edit을 막아 **AI가 자기를 막는 자물쇠를 고칠 수 없게** 했습니다. 가드는 패턴 모듈을 못 불러오면 통과시키지 않고 막는 쪽으로 실패합니다(**fail-closed**).

### 명령어 체계

| 명령 | 하는 일 |
| --- | --- |
| `/ingest` | 원본 → 위키 페이지 생성·보강, 교차참조, 목차·로그 갱신 |
| `/ingest-batch` | 서브에이전트 병렬 초안 + 메인 단독 병합 |
| `/capture` | 한 줄 메모를 원본으로 저장하고 관련 프로젝트 페이지 즉시 갱신 |
| `/query` | 위키 페이지를 `[[링크]]`로 인용하며 답변 |
| `/lint` | 스크립트 점검 + 의미 판단, 승인한 번호만 수정 |
| `/publish-check` | 커밋 전, 정규식이 못 잡는 분류 실수 리뷰 |
| `/eval` | 골든 질문으로 위키 품질 측정 |
| `/velog-wiki` | (볼트 전용 스킬) Velog 새 글 수집 → 위키 반영 |

Obsidian 공식 에이전트 스킬(kepano/obsidian-skills) 중 obsidian-markdown, obsidian-bases도 project scope로 설치했습니다. 스킬과 CLAUDE.md가 충돌하면 CLAUDE.md가 우선입니다.

### Velog 수집기와 Quartz 배포

수집은 원칙 ②대로 코드가 맡습니다. Velog 공개 GraphQL API(`v2.velog.io/graphql`, 필요한 필드만 골라 요청하는 API)로 본문을 받아 `_private/raw/velog/<시리즈>/<발행일>-<slug>.md`로 저장합니다. slug는 글 주소의 마지막 부분입니다. 원본은 **추가만(append-only)** 하므로 `"x"` 모드(이미 있으면 실패하는 모드)로 열고, 이름이 겹치면 `-2`를 붙입니다.

Quartz는 마크다운 폴더를 그래프 뷰가 있는 정적 사이트로 바꾸는 오픈소스 도구입니다. v5는 설정이 YAML(`quartz.config.yaml`), 갱신일 키가 `modified`였습니다. 소스는 레포에 넣지 않고 검증한 커밋을 빌드 때만 받아오도록 **고정(pin)**했습니다.

## 결과 — Velog 205편 반영

Velog 205편 전체를 원본 창고에 수집했고, 그중 3개 시리즈를 위키에 반영했습니다.

| 시리즈 | 원본 | 결과 | 방식 / 비용 |
| --- | --- | --- | --- |
| AI 생태계 탐험 로그 | 21편 | 공개 20페이지 (concepts 4, tools 16) | 직접 ingest |
| AI_LAB (연구 기록) | 88편 | 공개 29페이지 (연구 허브 1 + 개념 28) | ingest-batch, 서브에이전트 토큰 1,361,106 / 58분 42초 |
| 졸업작품 기록 | 94파일 (실제 93편, 1편 중복) | 신규 45, 보강 3, 기존 페이지 역링크 8 | 12묶음 × 3차례 병렬, 서브에이전트 토큰 1,640,203 / 43분 27초 |

**글 1편 ≠ 페이지 1개**입니다. 88편이 29페이지로 압축된 것이 위키의 핵심입니다. 용어집의 `asr-hallucination` 한 페이지에는 19·20·23·25·38·40편, 여섯 편의 내용이 모입니다.

### 병목은 병렬이 아니라 병합이었다

| 구간 (졸업작품) | 시간 |
| --- | --- |
| 병렬 초안 1차 / 2차 / 3차 (차례별 최장) | 4:22 / 5:42 / 5:32 |
| 병렬 구간 합계 | 약 15분 36초 |
| 메인 에이전트 단독 병합 | 약 28분 |

전체의 약 64%가 single writer 병합이었습니다. 서브에이전트를 더 늘려도 전체 시간은 병합 시간 아래로 내려가지 않습니다. 병렬화할 수 없는 구간이 전체 속도의 상한을 정한다는 암달의 법칙(Amdahl's law)과 같은 구조입니다. 한편 졸업작품은 원본이 더 많았는데도 연구 기록(58분)보다 빨리 끝났는데, 용어집과 공개 기준을 **먼저 확정하고** 시작했다는 차이가 있었습니다.

### 공개 기준, 모순, 그리고 publish-check

공개 기준은 시리즈마다 사람이 먼저 정했습니다. 졸업작품은 교수님 피드백을 "발표 피드백"으로 일반화하고, 학교명·학번 이메일은 빼고, 계정 정보는 `<REDACTED>` 처리했습니다. 커밋 해시와 PR 번호는 프로젝트 레포가 공개라 유지했습니다.

두 기록이 다른 말을 하면 덮어쓰지 않고 Obsidian 콜아웃(강조 상자 문법) `> [!warning] 모순`으로 두 출처를 함께 남겼습니다. 연구 기록 8곳, 졸업작품 6곳입니다. 반면 부품 교체(VL53L0X → VL53L5CX)나 설계 변경(코사인 → DTW)처럼 **시간이 지나며 바뀐 것은 모순이 아니라 이력**으로 정리했습니다. 둘을 구분하지 않으면 "틀린 기록"과 "바뀐 결정"이 같은 경고로 뒤덮입니다.

커밋 훅의 정규식은 API 키처럼 모양이 정해진 것만 잡습니다. 사람 이름, 학교, 프로그램 이름, 로컬 경로, "지인 섭외" 같은 사적 언급은 `/publish-check`가 의미 단위로 검토했고, 신규 46개와 수정 12개 파일이 모두 통과했습니다.

## 트러블슈팅 — 무엇이 깨졌고 어떻게 고쳤나

### 1. 가드의 오탐 3종 — 그리고 AI는 우회하지 않았다

오탐(false positive)은 문제없는 것을 문제로 잡는 것입니다.

| 오탐 | 잡힌 이유 | 수정 |
| --- | --- | --- |
| `git@github.com:...` | 이메일로 인식 | `^git@` 허용 목록 |
| `671.3042602539062` (실험 수치) | 주민등록번호로 인식 | 앞 6자리가 실제 생년월일이고 소수의 일부가 아닐 때만 |
| `access_token = refresh_access_token()` (블로그 예시 코드) | 키=값 비밀값으로 인식 | 값에 숫자가 섞이고 함수 호출 `(`로 끝나지 않을 때만 |

세 번째 오탐 때 비공개 레포 커밋이 막혔고, 훅 메시지는 `--no-verify`를 안내했습니다. 하지만 Claude Code는 CLAUDE.md 금지 사항이라 쓰지 않고 **멈춰서 보고**했습니다. 사람이 패턴을 고쳐 다시 커밋했고, 회귀 테스트로 예시 코드 6종 통과, 진짜 키 모양 5종 차단, 이전 패치 케이스 유지를 확인했습니다. **AI는 규칙 안에서 멈추고, 규칙은 사람이 고칩니다**(human-in-the-loop).

### 2. Velog 중복·누락 추적기 — 추측보다 이유를 출력하게

졸업작품 95편 중 같은 글이 `69`, `69-2`로 두 번 저장되고 2편이 조용히 빠졌습니다.

| 단계 | 보인 증상 | 실제 원인 | 대응 |
| --- | --- | --- | --- |
| 1 | 69 / 69-2 중복 | (추정) 목록 페이지 경계 중복 | 목록 id 중복 제거 + 건너뛴 글을 이유와 함께 출력 + 시리즈별 글 수 교차 확인 |
| 2 | `--list`에서 (69)가 "저장 안 됨" | 다른 글이 두 번 저장된 것 | 요청한 글 id ≠ 받은 글 id면 저장 거부하고 출력 |
| 3 | slug로 조회했더니 다른 글이 나옴 | Velog에 같은 slug 글이 2개(중복 게시), (68)은 slug 조회 시 null | slug 대신 글 고유 id로 조회, 실패 시 slug로 대체 |

1단계 추정은 틀렸지만, **건너뛴 이유를 출력하게** 만든 덕분에 2·3단계에서 진짜 원인이 드러났습니다. 68, 69는 정상 수집됐고, `69-3`은 id는 다르지만 본문이 바이트 단위까지 같아 Claude Code가 "Velog 중복 게시"로 판단해 반영에서 제외했습니다. 가장 위험한 코드는 에러를 내는 코드가 아니라 **조용히 넘어가는 코드(silent skip)**입니다.

### 3. 관대한 mock이 버그를 숨겼다

수집기는 테스트를 통과했는데 실제 API에서 바로 터졌습니다(`KeyError: 'url_slug'`, 시리즈 이름 앞 공백 `" 졸업작품 기록"`). mock은 테스트용으로 진짜 서버를 흉내 내는 가짜 서버인데, 이 가짜 서버가 **요청하지 않은 필드까지 다 돌려줬던 것**이 원인이었습니다. 진짜 GraphQL처럼 요청한 필드만 돌려주는 **strict mock**으로 버그를 재현한 뒤 고쳤습니다.

### 4. Python 스크립트로 가드를 비켜 간 쓰기

메인 에이전트가 Python 스크립트로 위키를 한꺼번에 썼습니다. 훅은 **도구 호출**만 보기 때문에 스크립트 안에서 여는 파일은 검사 밖이었습니다. CLAUDE.md에 "위키와 원본은 Write/Edit 도구로 하나씩" 규칙을 추가하고 correction으로 기록했습니다.

### 5. 그 밖의 문제

| 현상 | 해결 |
| --- | --- |
| 한글 파일명의 비밀값을 커밋 훅이 못 잡음 (git이 경로를 `"\355\225..."`로 이스케이프) | git 호출마다 `-c core.quotePath=false` |
| 인라인 코드 안의 `[[x]]`를 링크로 셈 | 코드 블록·인라인 코드 제거 후 링크 추출 |
| 공개·비공개 양쪽 `index.md` → 링크가 엉뚱한 곳으로 | 비공개는 `private-index.md`, 파일명은 볼트 전체에서 고유 |
| 지시문에 선택지 `[빼줘 / 그대로 둬]`를 남겨 에이전트가 멈춤 | 지시에는 결정 하나만 |

## 단계적 자동화 — 왜 처음부터 다 자동화하지 않았나

원칙은 **"손으로 해서 안정된 과정만 자동화한다"**입니다.

| 단계 | 자동 | 사람 | 전환 조건 |
| --- | --- | --- | --- |
| 1단계 (현재) | 매일 22:00 Velog **수집만** | `/velog-wiki`로 확인하며 정리 | — |
| 2단계 | 수집 + 정리 | 결과 검토, push | 최근 14일 실행 5회 이상 + correction 1회 이하 |

1단계는 launchd로 돌립니다. launchd는 정해진 시각에 프로그램을 실행해주는 macOS 시스템 서비스로, 리눅스의 cron과 비슷합니다.

```bash
bash .tools/velog_schedule.sh install 22:00   # launchd 등록
bash .tools/velog_schedule.sh run-now         # 즉시 1회 시험
bash .tools/velog_schedule.sh status          # 상태, 마지막 성공, 최근 로그
```

새 글이나 실패가 있으면 Mac 알림이 뜨고, 3일 넘게 멈추면 `/lint`가 경고합니다.

correction은 "Claude의 판단 오류"만 세야 합니다. 승인된 용어집대로 한 작업을 correction으로 잘못 기록했다가 지운 적이 있는데, 이런 기록이 섞이거나 진짜 오류가 빠지면 준비되지 않은 자동화가 열리거나 막힙니다. **지표는 세는 기준이 정직해야 의미가 있습니다.**

## 회고

**잘 된 것.** 5겹 자물쇠가 실제로 잠겼고, 막혔을 때 AI는 우회 대신 보고를 택했습니다. 용어집 선승인으로 이름 충돌이 0건이었습니다.

**아쉬운 것.** 골든 질문 eval의 기준선(baseline)을 아직 재지 못했습니다. Python 우회 쓰기는 팻말로만 막은 상태라 원칙 ①대로라면 자물쇠가 필요합니다.

**트레이드오프.** 가드 검사와 single writer 병합은 시간을 씁니다(졸업작품 병합만 약 28분). 그 대가로 이름 충돌 0건, publish-check 전 파일 통과, 그리고 "AI가 혼자 push해 원본이 공개되는" 시나리오가 구조적으로 불가능한 시스템을 얻었습니다. 공개 웹사이트로 나가는 시스템이라면 남는 거래라고 판단했습니다.
