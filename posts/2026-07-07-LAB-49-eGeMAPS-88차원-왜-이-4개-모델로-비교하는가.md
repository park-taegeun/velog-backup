## 개념 정리

### 1. SER

- Speech Emotion Recognition (음성 감정 인식)

```
SER (음성 감정 인식 = 과제 이름)
├── hand-crafted 방식 (MFCC·eGeMAPS + SVM/XGBoost)  ← 연구 노선
└── learned 방식 (wav2vec2/HuBERT 사전학습) ← "SER 모델"이라 부르는 것들
```

### 2. hand-crafted

- hand-crafted feature = 사람이 "이 특징이 중요하다"고 직접 설계해서 계산으로 뽑는 특징

ex.. F0·RMS·MFCC·eGeMAPS 88차원  

-> 전부 사람이 도메인 지식으로 미리 규칙을 짜둔 것들

### 3. learned feature (사전학습 오디오 모델)

- 사람이 뭘 뽑아라를 정해주지 않음
- raw 파형(waveform)을 통째로 넣으면 모델이 대량 데이터로 사전학습하면서 뭐가 중요한 특징인지 스스로 찾아냄

### 4. eGeMAPS

- extended Geneva Minimalistic Acoustic Parameter Set
- 음성 감정 및 어조 연구의 공통 표준 특징 세트

#### eGeMAPS가 실제로 뭘 하냐

```
[ 1단계 ]
- 프레임마다 원시 특징(LLD)을 뽑음 (이전에 추출한 3가지 특징 - MFCC, F0, RSM)
-> F0·에너지·jitter·shimmer·HNR·포먼트·MFCC 같은 걸 10ms 프레임마다 쭉 뽑음
- 그럼 발화마다 길이가 다른 시계열이 나옴

[ 2단계 ]
- 그걸 발화 단위 "통계"로 요약
-> 프레임 시계열을 그대로 안 쓰고 평균·표준편차·백분위·기울기 같은 통계값으로 압축함

ex..
F0의 평균 → 이 발화 전체가 얼마나 높은 톤이었나
F0의 표준편차 → 억양이 출렁였나 밋밋했나 (★강요된 동의 잡는 신호)
에너지의 기울기 → 발화가 점점 세졌나 죽었나

이렇게 통계로 요약하는 이유)
- 발화마다 길이가 다르면 모델에 넣기가 곤란함
-> 통계로 요약하면 길이가 몇 초든 무조건 88개 숫자 한 벌로 떨어짐
```

## 어조분석 Flow

```
[1] 음성 입력
      ↓
[2] 음향 특징 추출  ← eGeMAPS 88개 특징 추출
      ↓
[3] 특징표현 (functionals = 발화당 고정 88차원 벡터)
      ↓
[4] 모델 (SVM/XGBoost 등) ← 88개를 모델에 입력
      ↓
[5] 어조/감정 분류 출력
```

## 전제: 4개가 공유하는 울타리

4개를 고르기 전에 이미 두 가지가 정해져 있었다.

첫째, 입력은 전부 **eGeMAPS 88차원 고정 벡터**

- 발화가 4초든 8초든 무조건 88개 숫자 한 벌로 요약된다(functionals 방식) 그래서 고정 길이 입력을 받는 고전 ML이 궁합이 맞는다.

둘째, 전부 **hand-crafted 노선** 안이다

- 즉 사람이 "F0는 억양, jitter는 음질" 하고 설계한 특징만 쓰고, wav2vec2 같은 사전학습 오디오 모델은 안 쓴다.
- 이유는 성능이 아니라 **해석가능성**이다. 이 연구의 목적은 정확도를 극대화하는 게 아니라 "어조가 음향의 어느 차원에 박히는가"를 밝히는 것이라, 왜 그렇게 판단했는지 설명 못 하는 블랙박스는 목적 자체와 안 맞는다.

### 1. Logistic Regression

가장 투명한 기준점으로 넣었다.

Logistic Regression은 학습하면 `coef_`가 나오는데, 이게 88개 특징 각각에 대해 "이 특징이 커지면 어느 감정 쪽으로 얼마나 미는지"를 부호(+/-) 있는 숫자로 보여준다.

```
예: jitter 계수 +2.3  →  분노 쪽으로 강하게 민다
    F0 표준편차 계수 -1.1  →  중립(밋밋한 억양) 쪽으로 민다
```

이렇게 읽히니까 "어느 음향 차원이 어조를 만드는가"를 가장 직접적으로 답한다.  

그래서 해석의 기준점, 즉 앵커다.

### 2. Linear SVM

비교의 공식 기준선으로 넣었다.

eGeMAPS를 제안한 원논문(Eyben 2016)이 분류기로 딱 Linear SVM을 썼다.  

그래서 "eGeMAPS 하면 Linear SVM"이 사실상 교과서 조합이다.

이걸 넣으면 내 결과를 세계 표준과 같은 잣대로 비교할 수 있다. "우리 데이터에서 이 표준 조합이 몇 % 나오나"가 기준선이 된다(원논문 EMO-DB UAR 81.1%).

### 3. XGBoost / LightGBM

"직선 관계로 안 잡히면?"에 대한 답으로 넣었다.

위의 두 모델은 선형이다. "특징이 커지면 감정도 비례해서" 같은 직선 관계만 잡는다.

그런데 실제 어조는 안 그럴 수 있다. 예를 들어 F0가 아주 낮거나 아주 높을 때 둘 다 억압이고 중간은 중립이라면, 이건 꺾인 관계라 선형이 못 잡는다. XGBoost/LightGBM은 이런 비선형과 특징 간 상호작용을 잡는다.

여기서 중요한 건, 딥러닝을 안 쓰고 이걸 넣은 이유다. **비선형 모델 중에서 유일하게 해석이 살아있기 때문이다.** TreeSHAP이라는 방법으로 "이 예측에 어느 특징이 얼마나 기여했나"를 정확하고 빠르게 뽑는다. 즉 비선형인데도 블랙박스가 아니다.

### 4. RBF SVM

"해석을 포기하면 성능이 얼마나 오르나"의 상한선으로 넣었다.

RBF SVM은 고전 ML 중에 성능이 제일 높게 나오는 편이다(문헌 head-to-head에서 최상위). 그런데 커널이 비선형이라 해석이 거의 안 된다(느린 방법만 있다). 그래서 이 모델은 메인 후보가 아니라 천장 표시용이다.

이게 무슨 뜻이냐면, 결정을 돕는 잣대로 쓴다는 것이다.

```
LogReg 70%, RBF 72%  →  해석 지키는 비용 2%, 지킬 만하다
LogReg 70%, RBF 85%  →  해석 대가가 크다, 다시 고민
```

RBF를 쓰려고 넣는 게 아니라, "해석을 완전히 버리면 여기까지 오른다"는 상한선을 그어서 다른 모델의 선택을 정당화하거나 재고하게 만드는 역할이다.

## 정리: 왜 이 4개인가

| 모델 | 선형 여부 | 해석가능성 | 넣는 진짜 이유 |
| --- | --- | --- | --- |
| Logistic Regression | 선형 | 최상(투명) | 해석 기준점. 제일 투명하면서 성능도 정직 |
| Linear SVM | 선형 | 상 | 표준 조합. 세계 기준과 같은 잣대로 비교 |
| XGBoost / LightGBM | 비선형 | 상(TreeSHAP) | 비선형인데 해석 살아있는 유일 카드. 성능 천장 시도 |
| RBF SVM | 비선형 | 하 | 해석 버렸을 때의 상한선. 판단용 잣대 |

논리 구조로 보면 이렇다.

- **1·2번**: 해석이 완벽한 선형 두 개. 하나는 투명해서, 하나는 표준이라서
- **3번**: 해석을 지키면서 비선형으로 성능을 올려보는 도전
- **4번**: 해석을 버린 상한선. 내가 쓸 모델이 아니라 비교 잣대

해석과 정확도 축을 촘촘히 훑는 4개라, 돌려보면 "해석을 얼마나 지키면서 성능을 어디까지 낼 수 있나"가 한눈에 나온다.
