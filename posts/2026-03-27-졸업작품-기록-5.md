# 기획 발표 후 교수님 피드백

> 지금까지 정리한 기획 내용을 바탕으로 발표 자료를 만들었고, 교수님 앞에서 발표를 진행했다.
> 문제 인식부터 타겟 정의, 기존 제품 한계, 요구사항, 시스템 설계, ML 기술 스택까지 한 번에 발표했는데,
> 피드백 세 가지가 나왔다.

---

## 발표 내용 요약

발표 흐름은 아래와 같았다.

- **문제 인식** — 청각장애인 441,835명, 시각 신호표시기 보급률 0.3%
- **핵심 타겟** — 5060 중증 청각장애 1인 가구 (약 2만 명 추정)
- **기존 제품 한계 & 시장 공백** — 국내외 제품 모두 "현관 부착형 + ML 소리 분류 + 앱 푸시 알림" 동시 탑재 없음
- **요구사항** — 24시간 감지, 5초 이내 알림, ML 정확도 90% 이상
- **시스템 설계** — ESP32(INMP441 마이크) → Flask 서버(YAMNet + librosa) → 카카오톡 / 웹 대시보드
- **ML 기술 스택** — YAMNet Fine-tuning, TensorFlow + Keras, FSD50K / AudioSet 학습 데이터

## 교수님 피드백

### 1. 집집마다 초인종이 다를 텐데

> "집마다 초인종 소리가 다를 텐데, 옆집 초인종이 울려도 알림이 가는 거 아니냐?"

날카로운 지적이었다. 막연하게 "초인종 소리를 분류한다"고만 생각했지, 각 가정마다 초인종 음색이 전부 다르다는 걸 제대로 고려하지 않았던 거였다.

교수님이 제안한 방향은 **초기 설치 단계에서 사용자 초인종 소리를 직접 입력받는 방식**이었는데, 등록된 소리 패턴을 기준으로 분류하면 오탐을 줄일 수 있다는 아이디어였다.

### 2. 데모 시나리오를 제대로 준비해야 함

> "시연이 너무 단순할 것 같다. 데모 시나리오를 중요하게 고려해봐야 한다."

시스템이 잘 동작하더라도 시연 자체가 밋밋하면 임팩트가 떨어진다는 의미였다. 실제로 어떤 상황을 연출해서, 어떤 순서로 보여줄 것인지 시나리오 수준으로 구체화해야 한다는 피드백이었다.

### 3. 설치 용이성

현관에 기기를 부착하는 제품인데, 실제로 설치하기 쉬운 구조인지에 대한 피드백이었다. 하드웨어 형태나 고정 방식, 전원 처리 방법 같은 현실적인 부분까지 고려해야 한다는 뜻이었다.

## 받아들인 것들

세 가지 피드백 모두 기획 단계에서 당연히 짚었어야 했던 부분들이었다.

특히 초인종 소리 등록 문제는 "소리를 분류한다"는 큰 그림에만 집중하다가 실제 사용 환경을 제대로 상상하지 못한 결과였고, 데모 시나리오는 기술 구현에만 신경 쓰다 보니 "어떻게 보여줄 것인가"를 너무 뒤로 미뤘던 거였다.
