## 주요 설계 결정

### 라이브러리 선택

SparkFun_VL53L5CX_Arduino_Library 1.0.3을 1차로 채택하고, Adafruit_VL53L5를 폴백으로 lib_deps에 둘 다 등록했다. dead code elimination 덕분에 실제 link는 SparkFun만 됐다.

Adafruit 폴백 채택 방식은 PoC 단계에서 master 브랜치 추적(`https://github.com/adafruit/Adafruit_VL53L5.git`)으로 잡았는데, 근거가 세 가지였다. Adafruit 공식 lib은 breaking change 빈도가 낮고, PoC 기간이 ~3주로 짧고, SparkFun이 1차라서 Adafruit은 폴백 전용이라서였다. 8주차 prod 진입 시(7/13~) commit pin 전환을 재검토하기로 했고 DB3 row를 신설해뒀다.

### I2C 1MHz

사전 검증 ①에서 잡아둔 워크어라운드 그대로였는데, `Wire.setClock(1000000)`으로 설정했다. VL53L5CX datasheet 기준 I2C clock max가 1Mbits/s였고, SparkFun Example3_SetFrequency에서 1MHz 사용 사례를 확인했다.

참고한 OnlyFeet repo가 400kHz를 쓰고 있었는데 의도적으로 1MHz로 올린 거였다. datasheet max 한도 내에서 ToF polling 빈도를 높이는 게 사람 검증 응답 속도에 유리하다고 판단했다.

### 8x8 / 15Hz

datasheet 기준 8x8 mode 최대 주파수가 [1;15Hz]라서 그대로 15Hz로 설정했다. 4x4는 [1;60Hz]로 더 빠르지만 zone 해상도를 우선시했다. 사람 형체를 64 zone으로 잡는 게 핵심이었으니까.

### Core 0 + tofTask priority 3

카테고리 14 잠정안대로였는데, micTask priority 4와 분리했다. 5/21 PoC 통합 시 단독 테스트 4개 결과를 보고 재평가할 예정이다.

### graceful 처리

`initToF()` 실패 시 task spawn 생략 + `loop()` idle 진단 + 2회 retry + I2C bus scan 구조로 잡았다. OnlyFeet 패턴을 그대로 채택한 부분인데, 카메라 v1/v2 + 마이크 컨벤션과 동일한 "부품 부재 graceful" 패턴이었다.

## 컴파일 결과

```

Flash: [=         ]  11.1% (used 371,209 bytes from 3,342,336 bytes)
```

누적으로 보면 이렇다.

| 일자 | env | RAM | Flash | 비고 |
| --- | --- | --- | --- | --- |
| 5/8 | WiFi (poc) | 13.8% | 25.8% | TCP/IP stack heap |
| 5/9 | camera_v1 | 7.0% | 9.4% | esp_camera lib |
| 5/9 | camera_v2 | 7.0% | 9.4% | esp_camera lib |
| 5/10 | mic_dummy | 8.1% | 8.1% | I2S DMA 4KiB |
| 5/11 | tof_dummy | **6.1%** | **11.1%** | FW upload ~86KB |

마이크 대비 RAM이 내려가고 Flash가 올라갔는데, I2S DMA가 없어서 RAM은 줄었고 VL53L5CX FW upload buffer(~86KB)가 Flash를 올린 구조였다.

## 학습 14 catch 그물 작동 사례

5/10에 발굴한 학습 14가 5/11 ToF 작업에서 실제로 작동했는데, 이게 이날 가장 확인하고 싶었던 부분이었다.

자체 검증 ② "기존 컨벤션 일치" 항목에서 mic 컨벤션과 tof 코드를 라인 번호 기준으로 직접 비교했다.

- `mic_test.cpp:42-57` vs `tof_test.cpp:45-60` — graceful 처리 구조 동일
- Serial boot delay 패턴, task spawn 구조, loop idle 진단 방식까지 10개 항목 100% 일치

5/10에 위임 프롬프트와 실제 컨벤션 충돌이 발생했을 때 기존 컨벤션을 우선시하는 원칙(학습 16)을 박아뒀는데, 하루 만에 그 효과가 검증됐다. 카테고리 27/29 명문화가 실제로 catch 그물 역할을 하고 있었다.

학습 15 4단계 검증도 적용했는데 3/4 통과였다. 런타임 동작 검증(4단계)은 부품 도착 후(5/15+)로 보류됐다.
